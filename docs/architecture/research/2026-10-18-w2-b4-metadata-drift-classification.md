## Method

- Each item was checked against the real source file named in `packages/component-metadata/scripts/source-map.json`, and against the documented API decisions: the record header, ADRs and gap records.
- The classification rules:
  - **Add fact.** The symbol is a real public member of the shipped component: a signal `input()`/`output()`, a member of the exported `*Props` interface, or a key of the Vue `props`/`emits` options. No documented decision scopes it out.
  - **Exclude.** A record header states, with a reason, that the symbol is deliberately left unmodeled. A header that only mentions a symbol, without a reason, is not a decision.
  - **Checker false positive.** Needs evidence that the symbol is not public (not exported, `@internal`, private). No item met this.
  - **USER DECISION.** Neither a public fact nor documented. No item met this.
- Added facts follow each record's own conventions: field order, the source declaration order, its type and default, and a description taken from the source JSDoc or, where the source has none, written from what the source code does.

## Notes on the judgement calls

- **Table ng two-way companions (#15–#17), fix round 1.** The first pass excluded these as documented sibling outputs. Review found that the cited header lines (`table.ts:26-42`, `:64-66`) name them but give no reason to omit them, so they are not a documented decision. They are Angular two-way companions (`[(sortOrder)]`, `[(multiSortMeta)]`, `[(rows)]`), the same kind of API as `editingRowKeysChange` and `expandedRowKeysChange`, and in multi-sort mode `multiSortMetaChange` is the only sort output `onSort()` emits. Controller ruling: they are facts, with semanticIds `sort-order-changed`, `multi-sort-meta-changed` and `rows-changed`, matching Paginator's own-semanticId convention. Their exclusions were deleted.
- **"THREE events are modeled"** (the Table header) states a count. It gives no reason to omit the filter, lazy-load, editing or expansion events. Those 24 Table event items are therefore facts (27 with #15–#17). The header now says "THREE flagship events are detailed here", and a closing paragraph records this classification.
- **Accepted but not invoked** (#24, #27, #33, #34, and #41 for Vue `filter`). These are declared public members. Consumers can pass or bind them, so they are recorded, and each description says, from the source, that the component does not invoke or emit it yet.
- **Menu ng (#6–#10).** GAP-067 replaced the inert popup. The record header, the component `description` ("(React/Vue only)") and the ng `popup` description still described the old behaviour. They were corrected with the new facts. The existing test asserting an empty ng events array asserted the stale fact; it now asserts the two real outputs.

## Changes

- **Records.** `checkbox.ts`, `dialog.ts`, `menu.ts` and `table.ts` each have `metadataVersion` 1 → 2. Each bump equals `nextMetadataVersion(HEAD record, new record)`; the other four records are unchanged at 1.
- **Exclusions.** `packages/component-metadata/scripts/drift-exclusions.json` holds the 3 entries. Each one names `component`, `framework`, `apiKind`, `name`, `rationale` and `source`, and `source` is the record-header file:line.
- **Checker.** `check-api-drift.mjs`:
  - drift items now carry `apiKind`;
  - `collectDrift` returns structured items;
  - `applyExclusions(problems, exclusions, components)` returns `{ remaining, stale, invalid }`. It suppresses only an exactly matching `missing-in-record` item.
  - The CLI fails on any remaining item, any stale exclusion and any invalid exclusion. An exclusion is invalid if it names an unknown component, framework or apiKind, has a missing or extra field, uses a wildcard, has a source that is not a file:line or ADR, or duplicates another entry.
- **Regenerated.** The affected `.api.mdx` pages, `skills/{checkbox,dialog,menu,table}.md` and `packages/ai/context/llms*.txt`.
