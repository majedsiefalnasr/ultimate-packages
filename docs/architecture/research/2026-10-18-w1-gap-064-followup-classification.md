## Method

D2 allows exactly three dispositions: **in wave**, **exception**, or **confirmed closed**. Rules used here:

- **In wave.** The item falls inside what Spec §4 and W1-R1 to W1-R7 assign to one wave. No scope is added to a wave by this record.
- **Exception.** The item is out of every wave's scope and is not a defect in shipped behaviour (a story, a test-evidence limit, a wording note, or a decision already taken). Reason given. A **publish-level** exception is one that leaves an unmet Blueprint §40 or ADR-053 criterion, and must be entered in `BLUEPRINT_GAPS.md` §10 once the user approves it. **No exception below is publish-level.**
- **Confirmed closed.** A commit, test, CI run or decision record shows the item is done, and the item's own status text is stale.
- **Controller ruling.** Rows marked "(controller ruling)" were first flagged UNRESOLVED, because they are user-visible shipped-component deviations that no wave's §4 scope names. The controller ruled each one on 2026-10-18, and the rulings are applied below. No UNRESOLVED row remains.

## Residual modules (Spec §4, D2)

Method: a module is an exception "proof-set `uix-styles`" if its `*-style.ts` imports `@ultimate/uix-styles/<x>` (checked by grep for the import line, not for comments). Otherwise it is an exception "no upstream style" if `packages/themes/src/presets/aura` has no module for it. Aura holds no `avatar-group`, `button-group`, `dynamic-dialog`, `input-mask`, `scroll-top` or `style-class` module. The two avatar-group modules are the exception to the rule's literal result: they are assigned to W6 by controller ruling R5 (note A). The other 21 are exceptions and are assigned to no wave, because Spec §4 names no ng/Vue style work for them.

**Note A, avatar-group.** Applied literally, the rule gives "exception: no upstream style", and the G3 research (`2026-10-04-gap-064-g3-research.md` §10) already lists avatar-group among the "components without an Aura module". But the Aura `avatar` module does carry the group tokens (`group.borderColor` and `group.offset` in `packages/themes/src/presets/aura/avatar.ts`), upstream's avatar CSS includes `.p-avatar-group`, and Spec §4 treats the React `avatar-group` as a token consumer that "resolves only when a `UAvatar` on the same page has registered `avatar`". Ultimate's ng/Vue avatar-group reads an Ultimate-only variable, so it cannot be themed. **Controller ruling R5:** W6 (the avatar family) takes both modules: it registers `avatar` as an additional variables-only key and reads `avatar.group.*`.
