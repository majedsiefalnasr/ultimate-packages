## Mechanism assessment and exact-delta shortfall

The narrow C1 mechanism is to align the retained absolute span's effective vertical origin with Prime's direct-image origin while preserving the span's dimensions and image/clipping relationship. The desired result is second-image y16, without moving the root, first image or slider. This describes the required layout outcome, not an established CSS delta.

Current authored local rule:

```css
.u-image-compare > span { position: absolute; inset: 0; }
```

The span has no authored explicit height in this rule; its absolutely positioned image uses percentage width/height. Placement and sizing therefore cannot be treated as independent. Releasing vertical edge constraints to seek static placement would also require establishing the resulting wrapper size and percentage-image sizing. The unchanged image's measured static placement does not by itself prove the placement and dimensions of a differently constrained span.

The observed −3 px is a browser-used offset, not an upstream authored correction. The evidence does not justify encoding that number as a compensating declaration. It also contains no modified-span observation establishing an exact replacement that reproduces the direct-image origin while retaining the clip box. No exact property/value or before/after declaration delta is proposed.

This is an evidence limit, not a finding that C1 or DOM-preserving remediation is impossible. No C2/C3 substitution is selected.

## Preservation and risks

C1 can retain the same span, absolute positioning role, projected image, range input, `onSlide()` code and public API as source surfaces. No source evidence presently requires DOM/runtime/API expansion. Rendered behavior preservation remains unestablished without an exact delta.

| Area | Required preservation / unresolved risk |
| --- | --- |
| Clipping | The span remains the clip-path carrier; moving or resizing it can change the clip reference box, crop content or expose gaps |
| Image sizing | Percentage image dimensions depend on wrapper geometry; preserving image top alone is insufficient |
| Slide/interaction | The same handler must retain correct initial and slide clipping; unchanged handler code does not prove unchanged output |
| Focus | Existing slider and focus-visible placement must remain correct; overlay changes must not obscure them |
| RTL | The existing direction-dependent clip rule must remain valid against the adapted wrapper geometry |
| Other variants | Sized/default, slide, focus and RTL are regression guards; the inline-root displacement cannot be assumed to occur identically in them |
| Selector reachability | Element identities can remain unchanged, but no new reachability failure may be inferred absent merely from unchanged selectors |

The remediation target remains Angular `imagecompare/root-style`. A component-local span rule also applies to existing Angular ImageCompare variants, so their preservation must be demonstrated under the approved future boundaries. No other framework/component, token, shared rule, clipping mechanism or architectural convention is authorized.
