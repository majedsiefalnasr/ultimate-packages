## 4. Decisions needed

No "intentional" rows: exclusions are source comments, not accepted ADRs.

1. Default `value` (row 2/4). Options: (a) keep 0 (shows "0%"); (b) default to null/undefined and hide the label when null/0 like Prime. Consequence: (b) = Prime parity; (a) differs visibly. Recommendation: (b), or at least hide label for null.
2. Label/content override (row 7). Options: add template/render-prop/slot, or keep fixed label. Recommendation: add; it is the only way to localize or customize the label.
3. `color`/`valueStyleClass` (row 8). Options: add, or rely on tokens/CSS vars. Recommendation: defer to Phase 5 with pt.
4. React theme-key mismatch + hard-coded CSS (row 13): migrate to dt()/`progressbar` key per ADR-067 (progress-bar is not an exception). Recommendation: yes.
5. React indeterminate markup/animation (row 5): align to Prime container + inset animation, or keep own transform animation. Recommendation: align (RTL correctness).
6. pt (row 12): Phase 5 per D-PT.

## 5. Reference defects

- NGA/progressbar/progressbar.ts:36: host `aria-level` is non-standard on role=progressbar.
- PrimeVue hard-codes `value + '%'` in the label (no unit prop), unlike NG/React.
- PrimeReact throws Error for invalid mode (PRA ProgressBar.js:116); Ultimate treats it silently as indeterminate — Prime behavior, not necessarily to copy.
