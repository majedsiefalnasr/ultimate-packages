## 4. Decisions needed

1. **`type` and `align` props** — React `divider.tsx:17-20` states a deliberate "smaller surface" exclusion; no in-force ADR or user ruling found, so rows 3-4 stay _missing_ in all three frameworks. Options: (a) implement in all three (Prime parity, CSS already in `@primeuix/styles`); (b) record an ADR making them intentional (smaller API, users need custom CSS for dashed/aligned). Consequence of (b): rows become intentional, Prime migrants lose features.
2. **React hard-coded styling** (row 8-9) — D-SHARED #1; decide whether divider joins the ADR-067 exceptions or moves to `@ultimate/uix-styles/divider` tokens like NG/Vue.
3. **React `children != null`** (row 5) — keep (no empty wrapper) or follow Prime (always render content element). Matters for CSS spacing parity.
4. **NG deprecated `styleClass`** (row 7) — native `class` suffices; decide whether to ignore deprecated input (consistent with the iconfield "Option B" posture).

## 5. Reference defects

- `docs/prime-reference/components/divider.md:48` says unset horizontal alignment defaults to "left"; pinned sources centre it through inline styles (NG `dividerstyle.ts:6-10`, Vue `DividerStyle.js:5-9`, React `DividerBase.js:109-113`) while the class emitted is `-left` (NG `dividerstyle.ts:18`, Vue `DividerStyle.js:17`) — class vs actual position contradiction. Archive wins: effective default is centred.
- PrimeReact `DividerBase.js:103` repeats `.p-divider-dotted.p-divider-horizontal:before` for `border-left` instead of the vertical selector (vertical dotted never styled). Do not assume Ultimate must copy it.
