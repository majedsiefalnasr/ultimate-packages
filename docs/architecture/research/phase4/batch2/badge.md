## 4. Decisions needed

1. React standalone Badge. Options:
   - Add `UBadge` to React on the shared `@ultimate/uix-styles/badge` foundation. This closes rows 1-4, 7, 8 and 10, and lets `UButton` reuse it.
   - Keep Button's inline span only. This leaves seven gaps.

   Also decide severity naming: Prime-React `warning` or cross-framework `warn`. Recommendation: add the component, accept both `warn` and `warning`, and use the shared tokens.

2. Angular `pBadge` directive. Options:
   - Add it. PrimeNG ships it as current API, so this gives migration parity.
   - Keep the omission recorded in `docs/architecture/COMPONENT_INVENTORY.md:29`, which leaves the gap open; that entry is an inventory note, not an ADR.

   Recommendation: add it.

3. Vue `v-badge`. It is deprecated upstream. Options: provide a compatibility shim (migration aid that keeps a deprecated API alive) or record it as a deliberate gap pointing to OverlayBadge. Recommendation: deliberate gap, recorded in an ADR.
4. Angular OverlayBadge forwarding of `style`, `styleClass` and deprecated `size`. Options: forward `class`/`style` to the inner badge, or leave them on the wrapper only. Recommendation: forward `style` and `class` equivalents; skip the deprecated `size` and `styleClass`.
5. D-PT pass-through, including `pcBadge` and directive PT: common semantics with framework adapters, or Prime-shaped per framework. It stays missing until decided. Unstyled and dt: see D-SHARED item 5.

## 5. Reference defects

1. The PrimeVue `v-badge` deprecation appears only in a runtime `console.warn` (`PVA/badgedirective/BadgeDirective.js:7`). The `.d.ts` carries no `@deprecated` tag. REC:12 records this correctly; no record defect.
2. PrimeNG OverlayBadge CSS uses physical `right: 0` (`PNG/overlaybadge/style/overlaybadgestyle.ts:12`), while `@primeuix/styles` uses logical `inset-inline-end` (`PUS/overlaybadge/index.mjs`). Ultimate NG and Vue both use the logical form, which improves RTL over PrimeNG (REC:74). This is an implementation divergence in PrimeNG, not a record error.
3. No other conflict between documentation and source was found for this family.
