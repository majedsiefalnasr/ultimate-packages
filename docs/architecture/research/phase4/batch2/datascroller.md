## 4. Decisions needed

- **Data replacement (row3).** Restore Prime's eager reset-to-first-page on dataset replacement, or approve retaining the loaded page count. Reset matches migration behavior; retaining the window can be useful for refreshes but currently has no explicit ruling.
- **Inline container and semantics (rows6,12,14).** Match Prime's content-only scrolling and semantic ul/li with header/footer regions, or explicitly approve root scrolling and template-owned semantics. The latter changes scroll geometry and makes list accessibility dependent on each application.
- **API completeness (rows10,11,13,15).** Expose equivalent DOM refs, optional raw-item rendering, function/localized empty state and native attribute forwarding, or approve a smaller contract. A smaller contract prevents some documented Prime use cases, including accessible labeling via root ARIA.
- **Threshold geometry (row5).** Use pinned Prime's robust document-height calculation, or explicitly retain the simpler documentElement formula with stated constraints. The same buffer value is insufficient to guarantee identical trigger points.
- **PT/unstyled (rows16-17).** Implement the missing supported Prime surfaces; deferring them preserves missing classification. PT exclusion cannot be called intentional under the explicit ruling. No token/Aura decision is needed because ADR-067 already covers this family.

## 5. Reference defects

- **Listener leak:** P:109-118 only removes the window listener while loader is false, so toggling loader true leaves it attached; U:134-135 correctly removes the captured listener. REF:62 already records this. Do not require copying the defect.
- **Accessibility listProps claim:** pinned docs described in REF:76 mention listProps, but P:222-233 uses pt.list and B:52-69 has no listProps. The record correctly calls this a doc/source mismatch. Ultimate is missing the real PT/list capabilities, not a nonexistent listProps prop.
- **Ref typing mismatch:** implementation P:156-162 exposes reset/getContent/props in addition to typed load/getElement (REF:60). Analysis includes the source surface explicitly; absence of implementation-only members is not hidden behind the narrower declaration.
- No additional conflict between the reference record and the pinned implementation was established in this family.
