## 4. Phase 5 scope items (not classification disputes)

None of these items changes a verdict. No row becomes intentional without an in-force ADR or explicit user ruling.

1. **Custom content (row 14, React/Vue) and remove-icon customisation (rows 11–12, all).** Excluded by comments only.
   - A: Add React `template`, Vue default + `icon` + `removeicon` slots, `removeIcon` prop in all three, NG `removeicon` template. Consequence: parity; Chip becomes usable as the token renderer for MultiSelect/AutoComplete/InputChips.
   - B: ADR for a narrower contract. Consequence: rows become intentional; consumers cannot customise content.
2. **React remove veto and event shape (row 7).** A: match `{originalEvent, value}` + `return false` veto. B: keep the native event (record ADR). A also aligns React with how Prime data-driven chips work; NG/Vue oracles have no veto, so B keeps the three Ultimate frameworks closer to each other.
3. **Angular `chipProps` (row 18).** A: add. B: ADR excluding it. Matters only if MultiSelect/AutoComplete chip display passes chip props.
4. **Locale default for the remove label (row 10, NG).** Needs a translation/config source that Ultimate does not have (ADR-056 excludes a shared `config` surface). A: add a default label source. B: keep consumer-supplied only and record it.
5. **TimesCircle glyph (row 13).** A: add a `TimesCircleIcon` to the three cores. B: accept `UTimesIcon` as an Ultimate design choice (needs ruling).
6. **React tokens (row 25)** follow from ADR-067 already; no new decision, listed under shared finding 1.

Defect, not decision: NG empty host after removal (row 15).

## 5. Reference defects

1. PrimeVue's remove icon has no `role`/`tabindex` (PV:10), so it is not keyboard reachable although docs say removable chips are focusable. Already noted in R:71; confirmed. Ultimate Vue does better.
2. PrimeNG `close()` ignores `disabled` (PNG:233-236): a click on a disabled chip still removes it (only tabindex changes; whether `p-disabled` CSS blocks pointer events was not checked). Ultimate blocks it (U-NG:102). Do not copy.
3. R:32 says PrimeReact puts `p-chip-image` on the root — confirmed (PR-B:5-8); the `<img>` itself gets no class (PR:62-70). Record accurate.
