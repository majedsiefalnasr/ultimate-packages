## 1. Mapping

Masking fixed-format text and emitting its result is the mapping basis. Angular `InputMask` component ↔ `UInputMask` (`N:59-89`, root export `packages/ng/src/index.ts:19`, local barrel `packages/ng/src/input-mask/index.ts:1`). PrimeNG also has a standalone `[pInputMask]` directive (`PN:71-83`) for inputs and component hosts; Ultimate's component is not an equivalent attachable directive. React `InputMask` ↔ `UInputMask` (`R:34-56`, root export `packages/react/src/index.ts:17`). Vue `InputMask` ↔ `UInputMask` (`V:1-17`, root export `packages/vue/src/index.ts:22`, local barrel `packages/vue/src/input-mask/index.ts:1-2`, which also exports `createBaseInputMask`). Inventory read: `docs/inventory/angular-text-entry/README.md:9-26,52-56`, IR:11-31, IV:11-39.

## 4. Decisions needed

1. Vue Forms: ADR-039 is superseded. (A) integrate an independently reviewed forms mechanism corresponding to PrimeVue Forms; (B) record an explicit narrower v-model-only contract. A needs dependency/provenance and architecture review; B requires an explicit ruling. Recommendation: choose at platform level across form controls.
2. Mobile/composition: (A) match supported behavior with framework-native composition handling; (B) expressly constrain supported input methods. A has broader accessibility/device support; B limits users. Existing source comments do not authorize omission.
3. Angular mask directive: (A) support composition on existing inputs and component hosts like Prime; (B) explicitly retain a component-only API. A supports DatePicker-style reuse; B keeps a smaller API and needs a ruling.
4. Styling foundation: (A) use InputText tokens/registered stylesheet in each implementation, consistent with ADR-067; (B) an explicit exception. A aligns theming; B requires a decision. Per the user's explicit ruling, pt remains missing; it is not a new decision.
