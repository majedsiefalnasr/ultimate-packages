## 4. Decisions needed

- **Legend/template scope (rows 6-14).** Add the Prime-equivalent position/orientation and framework-native template/slot/render-prop surfaces, or explicitly approve a narrower public API in an in-force decision. Keeping the current API prevents Prime template and start-position use cases. Source comments asserting deliberate exclusions do not constitute a ruling.
- **Reference-defect rulings (rows 2 Vue, 12 Vue, 20 React/Vue).** Ruled by the user 2026-11-19: row 2 Vue partial (pinned fractional runtime; docs defect); row 12 Vue n/a (public slot not wired at Prime root); row 20 React/Vue complete (Ultimate guard is a safer extra). No further decision needed.
- **Numerical policy (rows 2,3,20,21).** Choose framework-specific Prime behavior, including raw React totals, fractional Vue sizing and segment filtering, or approve common normalized/guarded behavior. The common behavior reduces cross-framework variation but changes custom-range semantics. The raw-range versus percentage ARIA issue also merits an explicit accessibility decision rather than automatic copying.
- **React visual architecture (row16).** Follow ADR-067 by using Aura dt() and metergroup key, or amend that ADR to add an exception. Current literal styling does not satisfy the accepted policy. Separately choose whether column-reverse was intended: matching pinned Prime requires column ordering.
- **Attribute/unstyled/dt contracts (rows15,18,19).** Implement supported native attributes and base options, or record an explicit reduced contract; otherwise accessible naming and per-instance styling remain unavailable or unwired. For NG choose host versus inner meter ownership so supplied ARIA reaches the actual role.
- **PT (row17).** Add framework-native PT support to meet the explicit user ruling; deferring it leaves missing in all three. Reclassification as intentional would require a new explicit ruling, not the old ADR-056 scope text.

## 5. Reference defects

1. **NG custom label:** REF:101,108 says it is added after an unconditional default legend. P-N:63,101 actually guard default MeterGroupLabel with `!labelTemplate && !_labelTemplate`; the custom label replaces it. P-N:73 does contain a separate start-position bug (`labelTemplate || labelTemplate`, ignoring `_labelTemplate`). Neither behavior requires reproducing a defect in Ultimate.
2. **Vue icon slot:** REF:54,102 presents public icon customization. PL-V:4 declares the internal icon slot, but P-V:3-17 never forwards root slots into MeterGroupLabel. The public capability is not reachable through the pinned MeterGroup root. User ruling (2026-11-19): row12 Vue is n/a with this reference defect recorded.
3. **Vue sizing precision:** REF:55 says each meter is rounded. P-V:49-54 uses unrounded percent for width/height; only text and visibility use roundedPercent. Ultimate rounds actual sizing (U-V:55-67). User ruling (2026-11-19): pinned runtime governs, so row2 Vue is partial; REF:55 is a docs defect.
4. **Degenerate ranges:** P-R:32-36 and P-V:39-44 can divide by zero. Ultimate guards it (U-R:47-50, U-V:55-58). User ruling (2026-11-19): row20 React/Vue is complete; the guard is a safer Ultimate extra and NaN is not a parity target.
5. **ARIA explanation:** REF:73 suggests raw React total disagrees with custom maximum, but a raw sum can be correct in raw min/max units. The source establishes raw sum, not that a custom maximum alone is invalid. NG/Vue's normalized-total/raw-bounds combination is the concern explicitly recorded by inventory.

## 6. Unresolved

**U1 — NG vertical geometry (row5).** Ultimate omits P-N:237-240's getOuterHeight-based host stabilization while S-N:23 uses 100% meter-container height and U-N:53 uses percentage segments. Required check: render the same vertical items in pinned PrimeNG and Ultimate with no explicit height, then with a fixed-height host; compare root/meter container computed heights and segment rectangles. No browser or test is authorized in this analysis, so whether the missing stabilization produces a visible collapse is unresolved. This is one unresolved capability cell (NG), not three.
