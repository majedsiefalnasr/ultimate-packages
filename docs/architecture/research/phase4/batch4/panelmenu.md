## Decisions needed

Each item lists the options and their consequences; no recommendation or ordering is made.

1. **Expansion control.**
   - Option A: model- or key-driven expansion. Consumers could expand and collapse panels from outside and keep state keyed across data changes.
   - Option B: accept internal-only expansion. External control and restoring state are not possible.
2. **Keyboard model and header/region semantics.**
   - Option A: match the Prime model. Assistive-technology structure and Home/End and cross-level navigation would match Prime.
   - Option B: accept reduced coverage. That reduction applies to all three frameworks.
3. **React root visibility (known defect).**
   - Option A: treat it as a defect against the expected behaviour.
   - Option B: document a different intended structure. This needs a runtime check first (see the checks below).
4. **Group commands, templates, notifications and animation options, where Prime offers them.**
   - Option A: equivalent support.
   - Option B: document reduced customization. Consumers lose item and icon rendering control and panel event hooks.
5. **React theme architecture.** RS:3–13 uses literal values and no Aura tokens; the React theming ADR (ADR-067) covers this family.
   - Option A: consume Aura tokens.
   - Option B: an explicit, documented exception.
6. **PT.** Already decided by D-PT (missing). The rows are listed for completeness only.

## Reference defects

- **Nested list role.** PrimeNG uses `tree` for nested lists, while the reference docs say `group` (`panelmenu.md:84-90`). Resolved by your ruling: Angular row 5b is complete. The flag is kept.
- **Submenu-icon router branch.** The reference record notes a PrimeNG router branch that combines two template fields with `&&` where the plain-link branch uses `||` (`panelmenu.md:70-71`). I have not read this branch in the pinned source. It affects no Ultimate classification.
