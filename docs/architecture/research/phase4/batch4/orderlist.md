**What the embedded Listbox supports.** NLB and VLB behave the same:

- **Keys:** ArrowUp/Down wrap and skip disabled options. Home/End jump to the ends and do not skip disabled options. Enter, NumpadEnter and Space select the focused option. (NLB:222–252; VLB:134–164)
- **Not supported:** PageUp/PageDown, Shift range selection, Ctrl+A, type-ahead and `aria-activedescendant`. (NLB:41–45,66–75; VLB:15–24)
- **Focus:** the "focused" option is visual state only. Hover always moves that focus. (NLB:83; VLB:39)

  - PrimeVue Listbox: `aria-activedescendant` (PVL:29,59), PageUp/PageDown (PVL:271–275), type-ahead (PVL:305,632), range selection (PVL:393–530).

## Decisions needed

Each item lists the options and their consequences; no recommendation or ordering is made.

1. **Selection contract.**
   - Option A: bindable selection and change events in Angular and Vue, plus Prime's modifier-key behaviour in React. Consumers could observe and control selection.
   - Option B: keep internal selection. Consumers cannot set or read the selection from outside.
2. **Reorder event.**
   - Option A: emit Prime's reorder event with direction and original event.
   - Option B: keep value-only updates. Consumers cannot tell which move happened.
3. **Rendering and customization** (item templates, header and empty templates, filter templates, move icons).
   - Option A: equivalent support.
   - Option B: accept string-only rendering and fixed controls.
4. **Keyboard and focus model.** This is shaped by the embedded Listbox in Angular and Vue.
   - Option A: Prime-equivalent behaviour: range selection, Ctrl+A, PageUp/PageDown, type-ahead and `aria-activedescendant`. This also changes `UListbox`.
   - Option B: accept the reduced key set and visual-only focus. Screen readers do not get option-level focus.
5. **Default for `focusOnHover`** (React and Vue: false; Prime: true).
   - Option A: align the default. Behaviour changes for existing consumers who rely on false.
   - Option B: keep the difference and document it.
6. **Responsive opt-in (Angular) and React theme architecture.**
   - Angular: align the PrimeNG opt-in, or keep CSS that is always applied.
   - React (`packages/react/src/order-list/order-list-style.ts:3-10` uses literal values and no OrderList tokens): consume Aura tokens, or record an explicit ADR-067 exception.
7. **PT.** Already decided by D-PT (missing). Listed only.

## Reference defects

- PrimeNG declares a `header` input but renders only the header template (PN:114–118,164–168). Row 5 is judged against the template.
- PrimeNG declares `ariaLabelledBy`, `ariaFilterLabel` and `trackBy` but does not bind them in the inspected template (PN:86–144,189–193,243–247,273–277). They are not counted as working reference behaviour.
- `docs/prime-reference/components/orderlist.md:75-79`: the PrimeNG accessibility docs are copied from PickList, and the PrimeReact docs mention props that the pinned component does not have. The pinned runtime source was used instead.
