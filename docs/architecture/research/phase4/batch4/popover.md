**Evidence (Ultimate side, then Prime side)**

- **Row 1**
  - Ultimate: `popover.ts` show/hide/toggle; React `popover.tsx:23-27,77-95` (imperative handle); Vue `Popover.vue` methods with `emits` at `:45`.
  - Prime: N `popover/popover.ts`; R `overlaypanel/OverlayPanel.js:110-131`; V `popover/Popover.vue`.
- **Row 2**
  - Vue: Ultimate exposes `align()` (`packages/vue/src/popover/Popover.vue:127-134`) where Prime exposes `alignOverlay` (V `popover/Popover.vue:152-169`). The capability exists and only the name differs, so it is complete.
  - Placement quality is graded separately, in row 4.
  - NG/React: the React handle exposes only `toggle`/`show`/`hide` (`popover.tsx:23-27,95`). NG has no public align. Prime's `align`, `isVisible` and `getElement` are at N `popover.ts` and R `OverlayPanel.js`.
- **Row 3:** Prime NG and React re-show on a new target. Ultimate's toggle only hides or shows (React `popover.tsx:87-93`). Prime Vue only hides, so Vue is N/A.
- **Row 4**
  - Ultimate: rectangle bottom/left placement with no flip or clamp at `popover.ts:142-153`, `popover.tsx:66-74` and `Popover.vue:127-134`.
  - Prime: N `popover.ts:340-359`, R `OverlayPanel.js:173-195`, V `Popover.vue:152-169`.
  - React known defect: `Portal` renders null until its mount effect runs, so `contentRef` is null when the effect at `popover.tsx:97-102` calls `align()`. Inventory: `docs/inventory/react-overlays-notifications/README.md:78`.
- **Row 5:** This follows from row 4; Ultimate has no arrow or flip code in any of the three files.
- **Row 6:** In NG, the listener returns before resetting `selfClick` when `dismissable` is false (`popover.ts:157-172`). Inventory: `docs/inventory/angular-overlays-notifications/README.md:77`. React and Vue honour `dismissable` (`popover.tsx:110-116`, `Popover.vue:141-157`).
- **Row 7**
  - NG uses the escape registry (`popover.ts:193-207`).
  - React (`popover.tsx:104-108`) and Vue have no public `closeOnEscape`. Vue does not return focus to the target.
  - Prime: R `OverlayPanelBase.js` (`closeOnEscape`), V `Popover.vue` (focus return).
- **Rows 8–10**
  - Ultimate has only a document click listener and a window resize listener (`popover.ts:155-180`, `Popover.vue:141-164`), and hides on any resize.
  - Prime has `ConnectedOverlayScrollHandler` (N `popover.ts:456`, V `Popover.vue:232`), skips touch devices on resize, and has overlay-click buses (N `popover.ts:375-381`, R `OverlayPanel.js:84-122`, V `Popover.vue:122-130`).
- **Row 11**
  - NG hardcodes `body`; the pinned Prime NG default is also `'body'` (N `popover.ts:117-121`), but it is not configurable in Ultimate.
  - React has no `appendTo` prop (`popover.tsx:13-21`); Prime React has `appendTo`.
  - Vue: `BasePopover.ts:11` has `appendTo` defaulting to `"body"`.
- **Row 12:** NG hardcodes 1000 (`popover.ts:152`), React passes `undefined` (`popover.tsx:73`) and Vue uses only the overlay key (`Popover.vue:133`). Prime: V `BasePopover.vue:17-24`, and the matching R/N props.
- **Row 13:** Only PrimeReact has `showCloseIcon`, `closeIcon` and `ariaCloseLabel` (R `OverlayPanelBase.js`).
- **Row 14:** Ultimate comments `breakpoints` out (`BasePopover.ts:5`). Prime: V `BasePopover.vue:25`, R `OverlayPanelBase.js:110`, R `OverlayPanel.js:197-217`. Prime NG has no `breakpoints`.
- **Rows 15–16:** Prime NG and Vue focus content on show. Only Prime Vue uses a focus trap. Ultimate has neither.
- **Row 17:** Ultimate React adds `role="dialog"`/`aria-modal` (`popover.tsx:136`), but Prime React has none, so React is N/A.
- **Row 18**
  - Vue Prime uses `ptmi('root')` with `inheritAttrs: false` (V `Popover.vue:4,30`).
  - Ultimate Vue's root is `UPortal` (`Popover.vue:2`), with no `$attrs` binding to the dialog div.
  - NG/React expose no root id/class/style passthrough.
- **Row 19:** Prime has a `content` template/headless slot (N `popover.ts`, V `Popover.vue`). Prime React has only children, so React is N/A.
- **Row 20:** React `popover.tsx:17-19`, Vue `Popover.vue:45`, plus the NG outputs.
- **Row 21:** Ultimate renders with plain conditionals; Prime has transition/motion.
- **Row 22:** Ultimate base classes have no `pt` (`ng-core/src/basecomponent/base-component.ts`, `vue-core/src/base/base-component.ts`).
- **Rows 24–25:** NG `base-component.ts:21-24,35-36` has the `dt` and `unstyled` inputs. React `popover-style.ts` has no `dt()` tokens; this is an ADR-067 observation, not resolved here.
- **Row 26:** Vue `hide()` never calls `clearZIndex`; it is cleared only in `beforeUnmount`. Inventory: `docs/inventory/vue-overlays-notifications/README.md:76,86`. NG clears at `popover.ts:209-216`.

**Decisions needed (options only, no ranking)**

1. Anchoring contract: rectangle placement only, or Prime-equivalent flip, arrow and viewport clamping.
2. Whether `appendTo`, `autoZIndex`/`baseZIndex`, `closeOnEscape` and `breakpoints` become public API in every framework.
3. Focus policy: autofocus on show, and a focus trap in Vue.
4. React close-button surface (`showCloseIcon`, `closeIcon`, `ariaCloseLabel`).
5. Root attribute forwarding contract across frameworks.

**Reference defects (no verdict depends on them)**

- `docs/prime-reference/components/popover.md:82` says the component sets trigger `aria-expanded`/`aria-controls`. No pinned source does.
- The docs give `appendTo` default `'self'`; pinned PrimeNG has `'body'` (N `popover.ts:117-121`).
- PrimeReact adds the `p-overlaypanel-flipped` class only when unstyled (R `OverlayPanel.js:188-193`).
- PrimeNG's Escape `@HostListener` hides unconditionally (N `popover.ts:429-432`).
