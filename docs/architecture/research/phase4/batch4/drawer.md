**Decisions needed (options only, no ranking)**

1. Non-modal contract: whether `modal=false` removes the mask or makes it pass-through, and how outside-click works without a mask.
2. Vue ARIA: keep a fixed `complementary` role or use Prime Vue's `dialog` + `aria-modal` when modal.
3. Template, slot and headless surface (header, content, close icon, container).
4. Close-button customization (`closeIcon`/`closeButtonProps`) and a locale source for the close label.
5. `blockScroll`, configurable `appendTo` in NG/React, and the `autoZIndex`/`baseZIndex` default group (NG 1000 vs Prime 1100).
6. Single Escape path in Vue.

**Reference defects**

- **PrimeNG fullscreen inconsistency:**
  - The `p-drawer-full` class and the full-screen animation follow the `fullScreen` input (N `drawer.ts:222-232`, N `drawerstyle.ts:45-52`).
  - `data-p-full-screen` follows `position === 'full'` (N `drawer.ts:547-554`).
  - `docs/prime-reference/components/drawer.md:139` acknowledges the mismatch.
  - Per the user ruling, this is recorded as a defect and not as a separate required API. It does not affect row 3.
- `docs/prime-reference/components/drawer.md:95` says `aria-modal` is set for NG/React. The pinned sources do not set it.
- The docs say trigger `aria-expanded`/`aria-controls` are set. No source sets them.
- PrimeNG's local `onKeyDown` calls `hide(false)` without emitting `visibleChange` (N `drawer.ts:362-366`).
