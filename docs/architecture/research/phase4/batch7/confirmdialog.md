## Default flags

- `modal` and `closeOnEscape` defaults match as noted in row 7.
- PrimeNG `draggable` defaults true (`confirmdialog/confirmdialog.ts:352`); Ultimate does not expose it (row 11).

## Reference defects

- PrimeReact’s ConfirmDialog docs claim `alertdialog`; runtime renders Dialog `role="dialog"` and does not override (`dialog/Dialog.js:668-671`, `confirmdialog/ConfirmDialog.js:243-259`).
- PrimeNG’s `defaultFocus` helper searches `.p-confirm-dialog-accept` / `reject`, while the component style class names are `p-confirmdialog-accept-button` / `reject-button` (`confirmdialog.ts:551-570,110-143`; `style/confirmdialogstyle.ts:9-10`). Effective focus has not been runtime-checked.

## Rulings needed

1. **React alertdialog (row 6).** Recommended: follow pinned source, classify the docs-promised alertdialog capability N for PrimeReact and record a reference defect; Ultimate’s `dialog` role is then not a gap. Alternative: follow the docs contract, classify M because Ultimate React does not emit `alertdialog`.
2. **PrimeNG default focus (row 8).** Ruled 2026-11-21 (user approved, option A): N + reference defect. The source query is authoritative and matches no default-rendered element, so the effective feature is absent in pinned PrimeNG; Ultimate has no option for it, which is not a gap.
