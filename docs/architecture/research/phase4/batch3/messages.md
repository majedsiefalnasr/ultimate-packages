## 1. Mapping

PrimeReact `Messages` is an in-flow multi-notice container with an imperative list API, R `messages/Messages.js:13,32,87,116`. Ultimate React exports the single inline `UMessage` (`packages/react/src/message/message.tsx:32`, `packages/react/src/index.ts:72`): individual notices can be rendered in a consumer-owned list, but this is not the Prime container. Ultimate `UToast` (`packages/react/src/toast/toast.tsx:24,45,100`) has a similar show/clear handle, but is positioned as an overlay, so it is not an in-flow replacement; it is cited where it illuminates related functionality. No `Messages` export exists in the React root barrel. Mapping is by behavior, not name.

PrimeNG removed its plural `Messages` in v20 and PrimeVue does not ship it; Prime recommends a loop of single `Message` components (`docs/prime-reference/components/messages.md:9,15,16`). Ultimate exports `UMessage` in `packages/ng/src/index.ts:71` and `packages/vue/src/index.ts:78`; implementations read at `packages/ng/src/message/message.ts:37` and `packages/vue/src/message/Message.vue:1`. Those are useful declarative counterparts, but all cells in this family are n/a for these two frameworks because their pinned Prime has no plural component. Their individual Message parity belongs to the separate Message family.

## 4. Decisions needed

1. Choose a dedicated in-flow managed collection or document consumer-managed UMessage lists as the intended equivalent. The former enables a single ref and built-in list operations; the latter needs application-owned state and different usage.
2. Choose whether the collection should follow Prime's imperative methods and default close/expiry behavior or use a declarative API. The latter can share framework conventions, but needs a documented behavioral mapping and a deliberate expiry policy.
3. D-PT: decide implementation details and timing for section pass-through. Until implemented, it remains missing under the user's ruling.
4. Choose the live-region and dismissal behavior for an equivalent collection; assertive/atomic announcements and automatic expiry have different accessibility consequences from polite persistent notices.

## 5. Reference defects

PrimeReact types the close-icon pass-through key as `buttonIcon` while source reads `buttonicon`, `docs/prime-reference/components/messages.md:42,45`, R `messages/UIMessage.js:56`. The accessibility documentation claims `closeButtonProps` despite the API lacking it, and the styled-mode documentation lists `p-messages*` classes while the implementation emits `p-message*` (`docs/prime-reference/components/messages.md:83,90`). These are reference defects, not requirements to reproduce them.
