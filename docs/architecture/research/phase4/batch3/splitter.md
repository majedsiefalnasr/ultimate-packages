## Decisions and reference notes

1. Sizing state: initial sizes, persistence, Vue resetState/resize, dynamic panel count.
2. Panel surface: per-panel attributes/style, React panel ref and root attrs; configuration-only API itself is not a gap.
3. React keyboard/separator parity: Home/End/Enter and ARIA.
4. RTL drag in NG/Vue, where Prime handles RTL.
5. pt/unstyled timing belongs Phase 5.

Prime reference keyboard docs reverse NG/React layout descriptions (`docs/prime-reference/components/splitter.md:78,80`); pinned source is oracle and Ultimate matches arrows (P-N:370-406; P-R:235-269). PrimeNG applies `minSizes[0]` and `[1]` to every gutter (P-N:414-423; reference line 59); report does not require copying it.

Resolved row 3 (2026-11-21, source trace of U-N:194-227, U-R:107-143, U-V:119-150): partial + source-read defect in all three frameworks, from arithmetic on the clamp rather than a rendered check; whether the over-100 sizes produce a visible layout error depends on flex shrinking and was not rendered. Runtime checks for touch cleanup, RTL, storage, dynamic changes, and separator screen-reader focus unperformed. Reference line 57 claim about unsized panels sharing remaining space needs per-archive check; row 2 does not depend on it.
