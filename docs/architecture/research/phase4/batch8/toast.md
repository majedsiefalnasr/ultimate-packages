## Default flags

- PrimeNG and PrimeReact default to position `top-right` and message life 3000 ms; product defaults match.
- PrimeVue defaults position to `top-right`; its `ToastMessage` only starts a timeout when message.life is truthy (`ToastMessage.vue:86-100`), while Ultimate Vue sets container life to 3000 (`packages/vue/src/toast/BaseToast.ts:13-17`, `Toast.vue:105-113`): `life` row has `[default-differs]`. These are comparable/configurable choices, not a class difference under method 17; `sticky=true` can represent no timeout in Ultimate.
- PN duplicate-prevention flags both default false (`toast/toast.ts:339-344`); the optional capability is classified separately in row 21.

## Reference defects and ruling needed

PrimeReact's `ToastMessageOptions` type declares `group?: string` (`toast/toast.d.ts:107-110`), but pinned `Toast.js` routes by no group and `ToastBase.js:122-137` has no group prop; `show()` only appends to that instance (`Toast.js:34-38`). The routing row is U because honoring the declared contract versus executable source changes PrimeReact from M (declared capability not implemented) to N (no runtime capability), and can change the product verdict. Options: (A) score runtime only, classify PrimeReact routing N and record its unused type field as a reference defect; (B) treat the declared type as intended contract, leave Prime's own implementation defect noted and classify Ultimate React M for lacking group routing. Recommendation: A, because pinned runtime is the behavior oracle in DECISIONS.md §11. Keep U until the user rules. No other class-changing docs/source conflict found. PrimeVue's missing container `life` prop is a default/API difference, represented by a default flag in row 5; examples passing `life:3000` do not establish a container default.
