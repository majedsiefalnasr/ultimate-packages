# RadioButton

**Category:** Form · **Frameworks:** PrimeNG 21.1.9 · PrimeVue 4.5.5 · PrimeReact 10.9.9

## 1. Summary

RadioButton is a single-choice input: one visually hidden native `<input type="radio">` stretched over a styled round `box` that holds an inner `icon` dot. It exists in all three frameworks under the same name, but the way a _group_ of radios is wired differs sharply. PrimeNG groups radios by a shared `name` plus a form model through an injectable `RadioControlRegistry` (`primeng-21.1.9:packages/primeng/src/radiobutton/radiobutton.ts`). PrimeVue adds a separate `RadioButtonGroup` component that owns the value and the group name and is injected into child radios (`primevue-4.5.5:packages/primevue/src/radiobuttongroup/RadioButtonGroup.vue`, `primevue-4.5.5:packages/primevue/src/radiobutton/RadioButton.vue`). PrimeReact has no group concept at all: every radio is controlled individually through `checked` and `onChange` (`primeng-21.1.9:apps/showcase/doc/radiobutton/group-doc.ts`, `primevue-4.5.5:apps/showcase/doc/radiobutton/GroupDoc.vue`, `primereact-10.9.9:components/doc/radiobutton/groupdoc.js`).

The data tables embed RadioButton for single-selection columns (see section 9): PrimeNG and PrimeVue pass `binary`, PrimeReact passes a boolean `checked`.

- PrimeNG renders no wrapper: the `<p-radiobutton>` host is the root. `onAfterViewChecked` applies the `host` and `root` PT entries to it (`primeng-21.1.9:packages/primeng/src/radiobutton/radiobutton.ts`).
- Pass-through types: PrimeNG `root`, `input`, `box`, `icon` (`primeng-21.1.9:packages/primeng/src/types/radiobutton/radiobutton.types.ts`); PrimeVue the same four plus `hooks` (`primevue-4.5.5:packages/primevue/src/radiobutton/RadioButton.d.ts`); PrimeReact `root`, `icon`, `input`, `box`, `tooltip`, `hooks` (`primereact-10.9.9:components/lib/radiobutton/radiobutton.d.ts`). PrimeVue's `RadioButtonGroup` has only `root` and `hooks` (`primevue-4.5.5:packages/primevue/src/radiobuttongroup/RadioButtonGroup.d.ts`).
- State attributes: PrimeNG stamps `data-p-disabled`, `data-p-checked` and `data-p` on the host; PrimeVue stamps `data-p-checked`, `data-p-disabled`, `data-p` on the root and `data-p` on box and icon; PrimeReact stamps only `data-p-checked` on the root. The `data-p` value is built with `cn({ invalid, checked, disabled, filled, [size] })` in PrimeNG and PrimeVue; PrimeReact has no `data-p` (`primeng-21.1.9:packages/primeng/src/radiobutton/radiobutton.ts`, `primevue-4.5.5:packages/primevue/src/radiobutton/RadioButton.vue`, `primereact-10.9.9:components/lib/radiobutton/RadioButton.js`).

- PrimeNG selection logic: `onChange(event)` calls `select(event)` unless disabled; `select` sets `checked = true`, writes the model value, calls `onModelChange(this.value)` (the radio's own `value`, regardless of `binary`), calls `registry.select(this)` so same-group siblings run `writeValue(accessor.value)`, and emits `onClick({ originalEvent, value })`. `writeControlValue` computes `checked` as `value == this.value` (loose equality) or, in binary mode, `!!value`. A radio never un-checks itself through its own event (`primeng-21.1.9:packages/primeng/src/radiobutton/radiobutton.ts`).
- PrimeNG registry: `RadioControlRegistry` (`providedIn: 'root'`) holds `[NgControl, RadioButton]` pairs, and two radios are in one group when their controls share the same form `root` and the same `name()` (`primeng-21.1.9:packages/primeng/src/radiobutton/radiobutton.ts`). `onInit` resolves `this.injector.get(NgControl)` without an `optional` flag, so the component expects a forms directive on the element.
- PrimeVue selection logic: on native `change`, if neither disabled nor read-only it computes `binary ? !this.checked : this.value` and writes it through the group's `writeValue` when a group is injected, otherwise its own `writeValue`, then emits `change`. `checked` is `value != null && (binary ? !!value : equals(value, this.value))`, using deep equality from `@primeuix/utils/object` (`primevue-4.5.5:packages/primevue/src/radiobutton/RadioButton.vue`). `blur` also calls `formField.onBlur?.(event)` for `@primevue/forms`.
- PrimeVue group: `groupName` data starts from the `name` prop and falls back to `uuid('radiobutton-group-')` on mount and when `name` is cleared; the group provides `$pcRadioButtonGroup` and `$parentInstance` (`primevue-4.5.5:packages/primevue/src/radiobuttongroup/RadioButtonGroup.vue`, `primevue-4.5.5:packages/primevue/src/radiobuttongroup/BaseRadioButtonGroup.vue`). Its emits are `update:modelValue(value)` and `value-change(value)` (`primevue-4.5.5:packages/primevue/src/radiobuttongroup/RadioButtonGroup.d.ts`).
- PrimeVue form integration: `name`, `invalid`, `disabled`, `modelValue`, `defaultValue`, `formControl` come from `BaseEditableHolder` (`primevue-4.5.5:packages/core/src/baseeditableholder/BaseEditableHolder.vue`).
- PrimeReact `onChange`: builds `eventData = { originalEvent, value: props.value, checked: !props.checked, stopPropagation, preventDefault, target: { type: 'radio', name, id, value, checked } }`, but invokes `props.onChange` only if the input was toggled or the box `div` was clicked and the current state would flip. It returns early when `disabled` or `readOnly`, and does nothing (not even focus) when no `onChange` is provided (`primereact-10.9.9:components/lib/radiobutton/RadioButton.js`).
- PrimeReact `RadioButtonChangeEvent` extends `FormEvent`; the catalog lists `checked?`, `originalEvent?`, `target`, `value` (`docs/prime-reference/catalog/primereact.json`, module `radiobutton`, `events`). `RadioButtonBase.defaultProps` also holds `onClick: null` that is not declared in `radiobutton.d.ts` (`primereact-10.9.9:components/lib/radiobutton/RadioButtonBase.js`).
- Full API: catalog modules `radiobutton` in `docs/prime-reference/catalog/primeng.json`, `radiobutton`, `radiobuttongroup`, `radiobuttonstyle`, `radiobuttongroupstyle` in `docs/prime-reference/catalog/primevue.json`, and `radiobutton` in `docs/prime-reference/catalog/primereact.json`.

## 6. Usage guidance

- **Import** — import the module or component(s) from the framework entry; PrimeVue imports the group beside the radio (`primeng-21.1.9:apps/showcase/doc/radiobutton/import-doc.ts`, `primevue-4.5.5:apps/showcase/doc/radiobutton/ImportDoc.vue`, `primereact-10.9.9:components/doc/radiobutton/importdoc.js`).
- **Group** — a set of radios becomes one choice by giving them the same `name` and a shared model. Each radio carries its own `value`: PrimeNG and PrimeVue bind the model (`ngModel` / `v-model`) on every radio, PrimeReact sets `checked={ingredient === 'Cheese'}` and `onChange={(e) => setIngredient(e.value)}` per radio (`primeng-21.1.9:apps/showcase/doc/radiobutton/group-doc.ts`, `primevue-4.5.5:apps/showcase/doc/radiobutton/GroupDoc.vue`, `primereact-10.9.9:components/doc/radiobutton/groupdoc.js`).
- **Dynamic** — render radios from an array with a loop; the demos use object values in PrimeNG and PrimeReact (compared by `key` in React) and the `name` string in PrimeVue, and preselect the second entry (`primeng-21.1.9:apps/showcase/doc/radiobutton/dynamic-doc.ts`, `primevue-4.5.5:apps/showcase/doc/radiobutton/DynamicDoc.vue`, `primereact-10.9.9:components/doc/radiobutton/dynamicdoc.js`).
- **Filled** — `variant="filled"` gives a higher-emphasis look than the default outlined one (`primeng-21.1.9:apps/showcase/doc/radiobutton/filled-doc.ts`, `primevue-4.5.5:apps/showcase/doc/radiobutton/FilledDoc.vue`, `primereact-10.9.9:components/doc/radiobutton/filleddoc.js`).
- **Sizes** — `size="small"` and `size="large"` as alternatives to the base size; PrimeReact has no Sizes section and no `size` prop (`primeng-21.1.9:apps/showcase/doc/radiobutton/sizes-doc.ts`, `primevue-4.5.5:apps/showcase/doc/radiobutton/SizesDoc.vue`).
- **Invalid** — `invalid` marks failed validation; the demos drive it from "nothing selected" (`primeng-21.1.9:apps/showcase/doc/radiobutton/invalid-doc.ts`, `primevue-4.5.5:apps/showcase/doc/radiobutton/InvalidDoc.vue`, `primereact-10.9.9:components/doc/radiobutton/invaliddoc.js`).
- **Disabled** — `disabled` blocks editing and focus; PrimeNG and PrimeVue show two radios with a model preset to the second, PrimeReact shows one `checked disabled` radio (`primeng-21.1.9:apps/showcase/doc/radiobutton/disabled-doc.ts`, `primevue-4.5.5:apps/showcase/doc/radiobutton/DisabledDoc.vue`, `primereact-10.9.9:components/doc/radiobutton/disableddoc.js`).
- **Forms (PrimeNG)** — two sections: template-driven (`ngModel` with `name`, a `[invalid]` helper that is true after submit with nothing selected, `Message`, `Toast`, `MessageService` provider) and reactive (`formControlName` plus `Validators.required`) (`primeng-21.1.9:apps/showcase/doc/radiobutton/templatedrivenforms-doc.ts`, `primeng-21.1.9:apps/showcase/doc/radiobutton/reactiveforms-doc.ts`).
- **Forms (PrimeVue)** — wrap radios in `RadioButtonGroup name="ingredient"` inside a `@primevue/forms` `Form`, validate with a Zod resolver and show the error with `Message`; the radios themselves carry no `name` or model (`primevue-4.5.5:apps/showcase/doc/radiobutton/FormsDoc.vue`).
- **Forms (PrimeReact)** — N/A: no forms section in the PrimeReact doc (`primereact-10.9.9:pages/radiobutton/index.js`).
- **Accessibility** — label with `<label for>` + `inputId`, or with `aria-labelledby` / `aria-label` (`primeng-21.1.9:apps/showcase/doc/radiobutton/accessibility-doc.ts`, `primevue-4.5.5:apps/showcase/doc/radiobutton/AccessibilityDoc.vue`, `primereact-10.9.9:components/doc/radiobutton/accessibilitydoc.js`).
- **Pass Through** — PrimeNG and PrimeVue ship a PT viewer and options table; PrimeReact ships a wireframe page (`primeng-21.1.9:apps/showcase/doc/radiobutton/pt/PTViewer.ts`, `primevue-4.5.5:apps/showcase/doc/radiobutton/pt/PTViewer.vue`, `primereact-10.9.9:components/doc/radiobutton/pt/wireframe.js`).
- **Theming** — styled mode lists classes and (PrimeNG/PrimeVue) tokens; PrimeVue and PrimeReact also ship a Tailwind (unstyled) page (`primevue-4.5.5:apps/showcase/doc/radiobutton/theming/TailwindDoc.vue`, `primereact-10.9.9:components/doc/radiobutton/theming/tailwinddoc.js`, `primereact-10.9.9:components/doc/radiobutton/theming/styleddoc.js`).

No services or providers are required by the component itself. PrimeNG needs a forms directive on each radio (see section 5); the Forms demos additionally use `MessageService` for the toast.

## 7. Accessibility

- All three render a native `<input type="radio">` hidden with `opacity: 0` and stretched over the box, so it is the focusable element. The docs state that a hidden native radio is "only visible to screen readers" and that the name comes from `label` + input id or from `aria-labelledby` / `aria-label` (`primeng-21.1.9:apps/showcase/doc/radiobutton/accessibility-doc.ts`, `primevue-4.5.5:apps/showcase/doc/radiobutton/AccessibilityDoc.vue`, `primereact-10.9.9:components/doc/radiobutton/accessibilitydoc.js`, `@primeuix/styles-2.0.3:dist/radiobutton/index.mjs`).
- Keyboard (identical tables in all three docs): Tab moves to the checked radio of the group, or to the first one if none is checked; Left/Up moves to the previous radio and wraps to the last; Right/Down moves to the next and wraps to the first; Space checks the focused radio if unchecked. None of the three sources contains a key handler, so this is the browser's native radio-group behaviour and depends on the radios sharing a `name` (`primeng-21.1.9:apps/showcase/doc/radiobutton/accessibility-doc.ts`, `primevue-4.5.5:apps/showcase/doc/radiobutton/AccessibilityDoc.vue`, `primereact-10.9.9:components/doc/radiobutton/accessibilitydoc.js`).
- ARIA attributes on the input:
  - PrimeNG: `aria-label`, `aria-labelledby`, `aria-checked` (redundant on a native radio), `required` and `disabled` attributes; no `aria-invalid` (`primeng-21.1.9:packages/primeng/src/radiobutton/radiobutton.ts`).
  - PrimeVue: `aria-label`, `aria-labelledby`, `aria-invalid` (only when `invalid`), `disabled`, `readonly` (`primevue-4.5.5:packages/primevue/src/radiobutton/RadioButton.vue`). Native `readonly` has no effect on a radio, so the change guard is what blocks edits. `RadioButtonGroup` adds no role or ARIA attribute (`primevue-4.5.5:packages/primevue/src/radiobuttongroup/RadioButtonGroup.vue`).
  - PrimeReact: only props matching `DomHandler.ARIA_PROPS` are copied to the input, plus `required`, `readOnly`, `disabled`, `tabIndex`; the full `otherProps` set (including `aria-*`) is also spread on the root `div`, and there is no `aria-invalid` (`primereact-10.9.9:components/lib/radiobutton/RadioButton.js`).
- Doc wording differences: the PrimeVue and PrimeReact docs name the props `aria-labelledby` / `aria-label` and (PrimeVue) say `id` where the prop is `inputId`; the PrimeNG doc uses `ariaLabelledBy` / `ariaLabel` (`primevue-4.5.5:apps/showcase/doc/radiobutton/AccessibilityDoc.vue`, `primeng-21.1.9:apps/showcase/doc/radiobutton/accessibility-doc.ts`).
- Group semantics: neither `RadioButtonGroup` nor any other framework wrapper adds `role="radiogroup"`; grouping for assistive tech relies on the shared `name` only.

## 8. Theming

- Style classes (catalog `style.classes` for PrimeNG, `RadioButtonClasses` members for PrimeVue): `p-radiobutton`, `p-radiobutton-box`, `p-radiobutton-icon`, `p-radiobutton-input`; PrimeVue also `RadioButtonGroupClasses.root = p-radiobutton-group` (`primeng-21.1.9:packages/primeng/src/radiobutton/style/radiobuttonstyle.ts`, `primevue-4.5.5:packages/primevue/src/radiobutton/style/RadioButtonStyle.js`, `primevue-4.5.5:packages/primevue/src/radiobuttongroup/style/RadioButtonGroupStyle.js`).
- Root modifier classes (PrimeNG and PrimeVue): `p-component`, `p-radiobutton-checked`, `p-disabled`, `p-invalid`, `p-variant-filled`, `p-radiobutton-sm p-inputfield-sm`, `p-radiobutton-lg p-inputfield-lg`. PrimeVue's `p-invalid` comes from the injected group's `$invalid` when a group exists, otherwise from the radio's own `$invalid`. PrimeReact root classes are `p-radiobutton p-component` with `p-highlight` (checked), `p-disabled`, `p-invalid`, `p-variant-filled`; no size classes (`primereact-10.9.9:components/lib/radiobutton/RadioButtonBase.js`).
