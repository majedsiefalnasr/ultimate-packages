# TreeTable

**Category:** Data · **Frameworks:** PrimeNG 21.1.9 · PrimeVue 4.5.5 · PrimeReact 10.9.9

## 1. Summary

TreeTable renders hierarchical data (nodes with `children`) as a table. One column carries the expand/collapse toggle and indents each level, while the other columns show tabular data of the node. It combines the tree data model of **Tree** with most of the table features of **DataTable**: sorting (single and multiple), filtering, pagination, lazy loading, row selection (single, multiple, checkbox with parent/child propagation), column resizing, scrolling with fixed headers and frozen columns, context menu integration, and templating for caption, header, body, footer and summary areas. All three frameworks render a real `<table>`, and sorting, filtering, paging and selection operate on the node hierarchy rather than on a flat row list (`primeng-21.1.9:packages/primeng/src/treetable/treetable.ts`, `primevue-4.5.5:packages/primevue/src/treetable/TreeTable.vue`, `primereact-10.9.9:components/lib/treetable/TreeTable.js`).

The three implementations are noticeably different in how they are driven. PrimeNG mutates `node.expanded` on the data and uses directives (`ttSortableColumn`, `ttSelectableRow`, `ttEditableColumn`, ...) inside templates. PrimeVue and PrimeReact declare `Column` children and keep expansion as a key map (`expandedKeys`). PrimeNG is the only one with virtual scrolling; PrimeReact is the only one with stateful storage and striped rows; PrimeVue has neither cell editing nor column reordering.

## 2. Names & status

- Canonical name: **TreeTable** (component and class name in all three frameworks; PrimeNG selector `p-treeTable`).
- Menu label: **TreeTable** in the Data group of PrimeNG (`primeng-21.1.9:apps/showcase/assets/data/menu.json`, route `/treetable`, between Tree and VirtualScroller), PrimeVue (`primevue-4.5.5:apps/showcase/assets/menu/menu.json`, `to: "/treetable"`) and PrimeReact (`primereact-10.9.9:components/layout/menu.json`, `to: "/treetable"`).
- Legacy aliases: none as export names. PrimeNG also accepts the selectors `p-treetable` and `p-tree-table`.
- Deprecated:
  - PrimeNG: `styleClass` (since v20.0.0, use `class`) and `virtualRowHeight` (use `virtualScrollItemSize`; the setter logs a console warning).
  - PrimeVue: the `nodetogglericon` slot and the Column-child `rowtogglericon` slot (marked deprecated since v4.0, use `nodetoggleicon` and `rowtoggleicon`).
  - PrimeReact: none found.
- Not to be confused with **DataTable**, which is the flat-row table, or **Tree**, which is the list-style hierarchy without columns. The record for **Paginator** covers the paging UI embedded in this component.

## 3. Per framework

**PrimeNG 21.1.9**

- Import: `TreeTableModule` from `primeng/treetable` (`primeng-21.1.9:apps/showcase/doc/treetable/import-doc.ts`). The component is declared with `standalone: false` and the module declares and exports the sub-directives (`TreeTableToggler`, `TTSortableColumn`, `TTSortIcon`, `TTResizableColumn`, `TTReorderableColumn`, `TTSelectableRow`, `TTSelectableRowDblClick`, `TTContextMenuRow`, `TTCheckbox`, `TTHeaderCheckbox`, `TTEditableColumn`, `TreeTableCellEditor`, `TTRow`).
- Source `primeng-21.1.9:packages/primeng/src/treetable/treetable.ts` (about 4100 lines: `TreeTable`, `TreeTableService`, the directives above and the internal `TTBody` and `TTScrollableView`); style `primeng-21.1.9:packages/primeng/src/treetable/style/treetablestyle.ts`; types `primeng-21.1.9:packages/primeng/src/types/treetable/treetable.types.ts`; exports `primeng-21.1.9:packages/primeng/src/treetable/public_api.ts`.
- `value` is `TreeNode[]` from `primeng/api`; expansion is stored on the node (`node.expanded`). Columns are plain markup in the `header` and `body` templates, with `columns` only needed for dynamic columns and global filtering.
- `TreeTable extends BaseComponent<TreeTablePassThrough> implements BlockableUI`; a `TreeTableService` provider carries sort, selection, context-menu, UI-update and total-records subjects to the directives.

**PrimeVue 4.5.5**

- Import: `import TreeTable from 'primevue/treetable'` together with `import Column from 'primevue/column'` (`primevue-4.5.5:apps/showcase/doc/treetable/ImportDoc.vue`).
- Source `primevue-4.5.5:packages/primevue/src/treetable/TreeTable.vue` plus `TreeTableRow.vue` (recursive row), `BodyCell.vue`, `HeaderCell.vue`, `FooterCell.vue`; props `primevue-4.5.5:packages/primevue/src/treetable/BaseTreeTable.vue`; types `primevue-4.5.5:packages/primevue/src/treetable/TreeTable.d.ts`; style `primevue-4.5.5:packages/primevue/src/treetable/style/TreeTableStyle.js`.
- `value` is a node array (`key`, `data`, `children`, `selectable`, `style`, `leaf`, `loading`, `expandedIcon`, `collapsedIcon`). Expansion and selection are key maps: `expandedKeys` (`v-model:expandedKeys`, e.g. `{'0-0': true}`) and `selectionKeys` (`v-model:selectionKeys`). `dataKey` defaults to `'key'` and may be a function.
- Columns are `<Column>` children; the column that shows the toggle needs `expander`. Footer markup is only rendered when at least one column has a footer.

**PrimeReact 10.9.9**

- Import: `import { TreeTable } from 'primereact/treetable'` (`primereact-10.9.9:components/doc/treetable/importdoc.js`).
- Source `primereact-10.9.9:components/lib/treetable/TreeTable.js`, with `TreeTableBody.js`, `TreeTableRow.js`, `TreeTableBodyCell.js`, `TreeTableHeader.js`, `TreeTableFooter.js`, `TreeTableScrollableView.js`; defaults and CSS `primereact-10.9.9:components/lib/treetable/TreeTableBase.js`; types `primereact-10.9.9:components/lib/treetable/treetable.d.ts`.
- `value` is a `TreeNode[]`, columns are `Column` children, grouped headers use `headerColumnGroup` / `footerColumnGroup` (and frozen variants) built from `Row` and `ColumnGroup`. Expansion is `expandedKeys` plus `onToggle`; selection is `selectionKeys` plus `onSelectionChange`.
- Uses a stateful mode (`stateKey`, `stateStorage`) that saves and restores paging, sorting, filtering and expansion state.

## 6. Usage guidance

- **Basic:** pass the node array and describe columns; mark which column hosts the toggle. PrimeNG puts the `p-treeTableToggler` in the body template, PrimeVue and PrimeReact set `expander` on a `Column` (`primeng-21.1.9:apps/showcase/doc/treetable/basic-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/BasicDoc.vue`, `primereact-10.9.9:components/doc/treetable/basicdoc.js`).
- **Dynamic columns:** build columns from an array with a loop over it (`primeng-21.1.9:apps/showcase/doc/treetable/dynamiccolumns-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/DynamicColumnsDoc.vue`, `primereact-10.9.9:components/doc/treetable/dynamiccolumnsdoc.js`).
- **Column toggle:** drive visible columns with a MultiSelect (`primeng-21.1.9:apps/showcase/doc/treetable/columntoggle-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/ColumnToggleDoc.vue`, `primereact-10.9.9:components/doc/treetable/columntoggledoc.js`).
- **Column group:** PrimeNG and PrimeReact support header and footer row/column spans; the PrimeVue showcase has no such section (`primeng-21.1.9:apps/showcase/doc/treetable/columngroup-doc.ts`, `primereact-10.9.9:components/doc/treetable/columngroupdoc.js`).
- **Controlled:** manage expansion from the outside. PrimeVue and PrimeReact bind `expandedKeys` (`{'0-0': true}`); PrimeNG has no such input and the demo rewrites `expanded` on a copy of the data (`primeng-21.1.9:apps/showcase/doc/treetable/controlled-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/ControlledDoc.vue`, `primereact-10.9.9:components/doc/treetable/controlleddoc.js`).
- **Template:** customize the caption, header, body and summary/footer. The meaning of `header`/`footer` differs by framework (see section 11) (`primeng-21.1.9:apps/showcase/doc/treetable/template-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/TemplateDoc.vue`, `primereact-10.9.9:components/doc/treetable/templatedoc.js`).
- **Conditional style:** style rows through a class binding (`rowClassName` in PrimeReact) and cells in the body template (`primeng-21.1.9:apps/showcase/doc/treetable/conditionalstyle-doc.ts`, `primereact-10.9.9:components/doc/treetable/conditionalstyledoc.js`). PrimeVue has no dedicated section.
- **Pagination:** set `paginator` and `rows`; customize the layout with `paginatorleft` / `paginatorright` templates (PrimeNG), `paginatorTemplate` (PrimeVue, PrimeReact), or replace the whole bar with the `paginatorcontainer` slot (PrimeVue) (`primeng-21.1.9:apps/showcase/doc/treetable/paginatorbasic-doc.ts`, `primeng-21.1.9:apps/showcase/doc/treetable/paginatortemplate-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/pagination/PaginationBasicDoc.vue`, `primevue-4.5.5:apps/showcase/doc/treetable/pagination/PaginationTemplateDoc.vue`, `primevue-4.5.5:apps/showcase/doc/treetable/pagination/PaginationHeadlessDoc.vue`, `primereact-10.9.9:components/doc/treetable/paginator/basicdoc.js`, `primereact-10.9.9:components/doc/treetable/paginator/templatedoc.js`).
- **Sort, single column:** make a column sortable (`ttSortableColumn` on PrimeNG, `sortable` on a Column) (`primeng-21.1.9:apps/showcase/doc/treetable/sortsinglecolumn-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/sort/SingleColumnDoc.vue`, `primereact-10.9.9:components/doc/treetable/sort/singlecolumndoc.js`).
- **Sort, multiple columns:** set `sortMode="multiple"`; the docs say a meta key must be held when clicking headers (`primeng-21.1.9:apps/showcase/doc/treetable/sortmultiplecolumns-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/sort/MultipleColumnsDoc.vue`, `primereact-10.9.9:components/doc/treetable/sort/multiplecolumnsdoc.js`).
- **Sort, removable:** PrimeVue has `removableSort` (third click clears the sort). PrimeNG has no such prop and its section demonstrates `customSort` with `sortFunction`; PrimeReact has the prop but no showcase section (`primeng-21.1.9:apps/showcase/doc/treetable/sortremovable-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/sort/RemovableSortDoc.vue`).
- **Filter:** enable filters on columns and choose `filterMode`: with `lenient` a matching node keeps all descendants, with `strict` filtering continues into descendants. PrimeNG calls `filterGlobal`, PrimeReact binds `globalFilter` (`primeng-21.1.9:apps/showcase/doc/treetable/filter-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/FilterDoc.vue`, `primereact-10.9.9:components/doc/treetable/filterdoc.js`).
- **Selection, single:** `selectionMode="single"` with a binding; in PrimeVue and PrimeReact the binding is a key map (`primeng-21.1.9:apps/showcase/doc/treetable/selectionsingle-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/selection/SingleRowSelectionDoc.vue`, `primereact-10.9.9:components/doc/treetable/selection/singledoc.js`).
- **Selection, multiple:** `selectionMode="multiple"`. PrimeNG's text says a meta key is needed unless `metaKeySelection` is turned off (its runtime default is false); the PrimeVue and PrimeReact sections describe the same behaviour (`primeng-21.1.9:apps/showcase/doc/treetable/selectionmultiple-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/selection/MultipleRowsSelectionDoc.vue`, `primereact-10.9.9:components/doc/treetable/selection/multipledoc.js`).
- **Selection, checkbox:** `selectionMode="checkbox"` adds checkboxes that propagate to parents and children, and stores `{checked, partialChecked}` per key (`primeng-21.1.9:apps/showcase/doc/treetable/selectioncheckbox-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/selection/CheckboxRowSelectionDoc.vue`, `primereact-10.9.9:components/doc/treetable/selection/checkboxdoc.js`).
- **Selection events:** listen to node select and unselect (`onNodeSelect` / `onNodeUnselect` in PrimeNG, `node-select` / `node-unselect` in PrimeVue, `onSelect` / `onUnselect` in PrimeReact) (`primeng-21.1.9:apps/showcase/doc/treetable/selectioneventsc-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/selection/RowSelectionEventsDoc.vue`, `primereact-10.9.9:components/doc/treetable/selection/eventsdoc.js`).
- **Context menu:** pair with the ContextMenu component through the `contextMenu` and `contextMenuSelection` bindings (`primeng-21.1.9:apps/showcase/doc/treetable/contextmenu-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/ContextMenuDoc.vue`, `primereact-10.9.9:components/doc/treetable/contextmenudoc.js`).
- **Lazy loading:** set `lazy`, supply `totalRecords`, and fetch pages, sorted and filtered chunks on demand; PrimeVue additionally suggests loading only the root nodes and the children on node expansion (`primeng-21.1.9:apps/showcase/doc/treetable/lazyload-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/LazyLoadDoc.vue`, `primereact-10.9.9:components/doc/treetable/lazyloaddoc.js`).
- **Loading:** a loading mask over the table, or a Skeleton placeholder while data is fetched (`primeng-21.1.9:apps/showcase/doc/treetable/loadingmask-doc.ts`, `primeng-21.1.9:apps/showcase/doc/treetable/loadingskeleton-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/loading/LoadingMaskDoc.vue`, `primevue-4.5.5:apps/showcase/doc/treetable/loading/LoadingSkeletonDoc.vue`).

In scrollable tables PrimeNG needs a `colgroup` template (`primeng-21.1.9:apps/showcase/doc/treetable/columnresizefit-doc.ts`, `primeng-21.1.9:apps/showcase/doc/treetable/columnresizeexpand-doc.ts`, `primeng-21.1.9:apps/showcase/doc/treetable/columnresizescrollable-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/resize/FitModeDoc.vue`, `primevue-4.5.5:apps/showcase/doc/treetable/resize/ExpandModeDoc.vue`, `primereact-10.9.9:components/doc/treetable/resize/fitmodedoc.js`, `primereact-10.9.9:components/doc/treetable/resize/expandmodedoc.js`).

- Services needed: none are provided by the application. PrimeNG provides `TreeTableService` itself.

## 7. Accessibility

- Table markup: PrimeNG and PrimeVue set `role="treegrid"` on the `<table>`; PrimeReact sets `role="table"` on both the root and the table. The PrimeNG and PrimeVue docs describe the default role as `table` and PrimeVue even copies the sentence "DataTable uses a treegrid element", so docs and source disagree (`primeng-21.1.9:apps/showcase/doc/treetable/accessibility-doc.ts`, `primevue-4.5.5:apps/showcase/doc/treetable/AccessibilityDoc.vue`, `primereact-10.9.9:components/doc/treetable/accessibilitydoc.js`).
- Structure: `thead`, `tbody`, `tfoot` use `rowgroup`; rows use `row`; header cells use `columnheader`; body cells use `cell`. Sortable headers carry `aria-sort` (`ascending` or `descending`) and `tabindex="0"`.
- Hierarchy: each row has `aria-level` (`level + 1`) and `aria-expanded` (PrimeVue only when the node has children). PrimeVue and PrimeReact set `aria-posinset` and `aria-setsize` themselves. The PrimeNG doc asks the app to supply `aria-posinset` and `aria-setsize`, `aria-label` and `aria-describedby`, and the `ttRow` directive manages only `aria-expanded` and `aria-level`.
- Selection: rows get `aria-selected`; PrimeVue and PrimeReact also set `aria-checked` in checkbox mode. PrimeNG wraps the Checkbox component, which sets `role="checkbox"` and `aria-checked`. Editable cells need manual ARIA in PrimeNG and PrimeReact.
- Toggle button: a `<button>` with `tabindex="-1"` and an `aria-label` from the locale (`expandRow` / `collapseRow` in PrimeNG's `config.translation.aria`; `expandLabel` / `collapseLabel` in PrimeReact). It is reached by the arrow keys on the row, not by Tab.
- Keyboard on rows (source): ArrowDown and ArrowUp move between visible rows; ArrowRight expands a collapsed node (PrimeNG and the docs: opens, then moves to the first child); ArrowLeft collapses or moves to the parent; Enter and Space select (PrimeVue and PrimeReact also accept NumpadEnter and skip clickable targets); Tab enters at the first selected row (Shift+Tab the last). Home and End jump to the first and last row of the same level; the PrimeNG doc omits them although `ttRow` handles them.
- Keyboard on headers: Enter sorts in all three; Space sorts in PrimeVue and PrimeReact (`onHeaderKeyDown` checks `event.code === 'Space'`). The PrimeNG doc lists Space too, but `TTSortableColumn` only binds `keydown.enter`.
- Roving focus: rows have `tabindex="0"` and the component rewrites tabindex values so that the selected row is the entry point (PrimeReact `TreeTableRow.js` rewrites `tabIndex` on Tab).
- The embedded Paginator brings its own accessibility behaviour, see **Paginator**.

## 9. Relationships

- **DataTable**: the closest sibling. TreeTable reuses its option vocabulary (`sortMode`, `filterMode`, `lazy`, `metaKeySelection`, `resizableColumns`, `paginator`) but works on `TreeNode` hierarchies. Its expansion is tree-based, and the PrimeVue and PrimeReact TreeTable have no virtual scroll (only PrimeNG offers `virtualScroll`).
- **Tree**: shares the node model (`TreeNode` in PrimeNG and PrimeReact), the `expandedKeys` / `selectionKeys` key-map style (PrimeVue, PrimeReact) and the `{checked, partialChecked}` checkbox state. Choose Tree when columns are not needed.
- **OrganizationChart**: another consumer of the same `TreeNode` model.
- **Paginator**: embedded for paging; PrimeNG uses `p-paginator`, PrimeVue `primevue/paginator`, PrimeReact `Paginator`.
- **ContextMenu**: integrates through `contextMenu` / `contextMenuSelection` (PrimeNG calls `contextMenu.show(event)`).
- **Checkbox**, **Badge** (multi-sort index), **Ripple**, **Skeleton** (loading demos), **MultiSelect** (column toggle demos), **InputText** (filter inputs) are used or demonstrated.
- **Scroller** (PrimeNG only): backs `virtualScroll`.

## 11. Framework differences

| Aspect                          | PrimeNG                                                                   | PrimeVue                                              | PrimeReact                                        |
| ------------------------------- | ------------------------------------------------------------------------- | ----------------------------------------------------- | ------------------------------------------------- |
| Column declaration              | Markup inside `header` and `body` templates and directives                | `<Column>` children                                   | `<Column>` children                               |
| Toggle placement                | `p-treeTableToggler` in the body template                                 | Column with `expander`                                | Column with `expander`                            |
| Expansion state                 | Mutates `node.expanded`; no `expandedKeys` input                          | `expandedKeys` key map (`v-model`)                    | `expandedKeys` key map plus `onToggle`            |
| Selection value                 | `selection` (node objects) or `selectionKeys`                             | `selectionKeys` key map                               | `selectionKeys` key map                           |
| `header` / `footer`             | Column header and footer rows; caption and summary are separate templates | Caption and summary areas (slots)                     | Caption and summary areas (props)                 |
| Meta key default                | `false`                                                                   | `false`                                               | `false` at runtime, `true` in the `.d.ts`         |
| Removable sort                  | N/A (use `customSort`)                                                    | `removableSort`                                       | `removableSort`                                   |
| Virtual scroll                  | `virtualScroll` with `p-scroller`                                         | N/A                                                   | N/A                                               |
| Column reorder and cell editing | Yes (`reorderableColumns`, `ttEditableColumn`)                            | No                                                    | Yes (`reorderableColumns`, Column `editor`)       |
| Frozen columns                  | `frozenColumns` + `frozenWidth`                                           | Column `frozen` + `alignFrozen` (sticky)              | `frozenWidth` + frozen column groups              |
| Stateful storage                | N/A                                                                       | N/A                                                   | `stateKey`, `stateStorage`                        |
| Striped rows                    | N/A                                                                       | N/A                                                   | `stripedRows`                                     |
| Size                            | CSS class `p-treetable-sm` / `-lg`                                        | `size` prop                                           | N/A                                               |
| Root ARIA role                  | `treegrid` on the table                                                   | `treegrid` on the table                               | `table` on root and table                         |
| `aria-posinset` / size          | Supplied by the app                                                       | Set by the component                                  | Set by the component                              |
| Space on sort header            | Not bound (docs claim it)                                                 | Sorts                                                 | Sorts                                             |
| Class names                     | `p-treetable-*` family                                                    | Same family, own header-cell and body-cell names      | Older `p-highlight`, `p-link`, `p-column-*` names |
| Design tokens                   | `@primeuix/themes`                                                        | `@primeuix/themes`                                    | N/A                                               |
| Pagination defaults             | `'{currentPage} of {totalPages}'` report, `pageLinks` 5                   | `'({currentPage} of {totalPages})'`, `pageLinkSize` 5 | Same as PrimeVue                                  |

Defaults that differ between declaration and runtime in PrimeReact (`TreeTableBase.js` against `treetable.d.ts`): `metaKeySelection` is `false` at runtime but the `.d.ts` says `true`; `stateStorage` is `null` at runtime but the `.d.ts` says `session`, and `getStorage` throws for any value other than `local`, `session` or `custom` when `stateKey` is used alone; `paginatorDropdownAppendTo` is `null` against `document.body` in the `.d.ts`; `first` is `null` against `0`; `emptyMessage` is `null` (falls back to the locale text) against `'No results found'`.
