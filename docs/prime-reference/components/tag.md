# Tag

**Category:** Misc · **Frameworks:** PrimeNG 21.1.9 · PrimeVue 4.5.5 · PrimeReact 10.9.9

## 1. Summary

Tag is a small inline label that shows a short value, with an optional leading icon, a severity colour variant and a rounded pill shape. All three frameworks ship it under the same name (`primeng-21.1.9:packages/primeng/src/tag/tag.ts`, `primevue-4.5.5:packages/primevue/src/tag/Tag.vue`, `primereact-10.9.9:components/lib/tag/Tag.js`). The class vocabulary (`p-tag`, `p-tag-icon`) is shared, but the three implementations differ in how projected content is placed, in the severity names they accept and in the state attributes they emit (section 11).

## 2. Names & status

- Canonical name: **Tag**, identical in PrimeNG 21, PrimeVue 4 and PrimeReact 10. The shared glossary (`GLOSSARY.md`) has no Tag entry, and because the name is the same everywhere no legacy alias is needed.
- Deprecated: the PrimeNG `styleClass` input is marked `@deprecated since v20.0.0`, with `class` as the replacement (`primeng-21.1.9:packages/primeng/src/tag/tag.ts` lines 50 and 53). No Tag member is deprecated in the PrimeVue or PrimeReact sources.
- Catalog entries for module key `tag` are in `docs/prime-reference/catalog/primeng.json`, `docs/prime-reference/catalog/primevue.json` and `docs/prime-reference/catalog/primereact.json`.
- The showcase menus list Tag under Components > Misc at route `/tag` in all three frameworks (`primeng-21.1.9:apps/showcase/assets/data/menu.json`, `primevue-4.5.5:apps/showcase/assets/menu/menu.json`, `primereact-10.9.9:components/layout/menu.json`).
- Tag is not Badge or Chip. Its relationships to those components are listed in section 9.

- PrimeNG projects content with `<ng-content>` first, then renders the icon, then always renders the label span (`primeng-21.1.9:packages/primeng/src/tag/tag.ts` lines 20-27).
- PrimeVue renders the icon and then a default `<slot>` whose fallback is the label span. Supplying default slot content therefore replaces the label (`primevue-4.5.5:packages/primevue/src/tag/Tag.vue` lines 2-7).
- PrimeReact renders the icon, the value span and then an unnamed `span` wrapping `children` (`primereact-10.9.9:components/lib/tag/Tag.js` lines 51-57).
- Icon handling: PrimeNG renders an icon span only when `icon` is set and no template exists (`primeng-21.1.9:packages/primeng/src/tag/tag.ts` lines 21-26); PrimeVue uses the `icon` slot when present, otherwise an icon span with the `icon` class string (`primevue-4.5.5:packages/primevue/src/tag/Tag.vue` lines 3-4).
- Data attributes: PrimeNG sets `data-p` on the host from `dataP` (`primeng-21.1.9:packages/primeng/src/tag/tag.ts` line 34). PrimeVue sets `data-p` on the root from `dataP` (`primevue-4.5.5:packages/primevue/src/tag/Tag.vue` line 2). PrimeReact sets no `data-p`; it emits `data-pc-name` and `data-pc-section` from its `ComponentBase` dataset prefix (`primereact-10.9.9:components/lib/componentbase/ComponentBase.js` lines 455 and 491-492). The PrimeReact snapshot shows `data-pc-name="tag"` and `data-pc-section="root"` on the root (`primereact-10.9.9:components/lib/tag/__snapshots__/Tag.spec.js.snap`, around line 106).
- The `data-p` state keys are `rounded` and the severity name in PrimeNG and PrimeVue (`primeng-21.1.9:packages/primeng/src/tag/tag.ts` lines 97-102 and `primevue-4.5.5:packages/primevue/src/tag/Tag.vue` lines 19-24).

## 6. Usage guidance

- **Basic label.** Set `value` to the text to show. The three basic docs use this form (`primeng-21.1.9:apps/showcase/doc/tag/basic-doc.ts`, `primevue-4.5.5:apps/showcase/doc/tag/BasicDoc.vue`, `primereact-10.9.9:components/doc/tag/basicdoc.js`).
- **Severity.** Pick one of the severity names to change the colour variant. The PrimeNG doc shows `warn` (`primeng-21.1.9:apps/showcase/doc/tag/severity-doc.ts`), the PrimeVue doc shows `warn` (`primevue-4.5.5:apps/showcase/doc/tag/SeverityDoc.vue`), and the PrimeReact doc shows `warning` (`primereact-10.9.9:components/doc/tag/severitydoc.js`). Use the spelling each framework's union accepts (section 11).
- **Pill shape.** Set `rounded` to render the tag as a pill. The docs show it on every severity (`primeng-21.1.9:apps/showcase/doc/tag/pill-doc.ts`, `primevue-4.5.5:apps/showcase/doc/tag/PillDoc.vue`, `primereact-10.9.9:components/doc/tag/pilldoc.js`).
- **Leading icon.** Pass an icon. In PrimeNG and PrimeVue the value is a font icon class such as `pi pi-user` (`primeng-21.1.9:apps/showcase/doc/tag/icon-doc.ts`, `primevue-4.5.5:apps/showcase/doc/tag/IconDoc.vue`). In PrimeReact the prop accepts an `IconType`, and the doc uses a font icon (`primereact-10.9.9:components/doc/tag/icondoc.js`).
- **Custom content.** The template docs project extra content into the tag, such as a flag image and text. Because the three frameworks place projected content differently, do not depend on replacement or appending behaviour without checking section 11 (`primeng-21.1.9:apps/showcase/doc/tag/template-doc.ts`, `primevue-4.5.5:apps/showcase/doc/tag/TemplateDoc.vue`, `primereact-10.9.9:components/doc/tag/templatedoc.js`).
- **Accessibility.** The accessibility docs say Tag has no default roles and that extra attributes reach the root, so ARIA and `tabIndex` can be added by the consumer (`primeng-21.1.9:apps/showcase/doc/tag/accessibility-doc.ts`, `primevue-4.5.5:apps/showcase/doc/tag/AccessibilityDoc.vue`, `primereact-10.9.9:components/doc/tag/accessibilitydoc.js`). See section 7.
- **Passthrough customisation.** The PT docs show how to reach the root, icon and label sections through the framework's PT options (`primeng-21.1.9:apps/showcase/doc/tag/pt/PTViewer.ts`, `primevue-4.5.5:apps/showcase/doc/tag/pt/index.vue`, `primereact-10.9.9:components/doc/tag/pt/wireframe.js`). Section 4 gives the keys.
- **Theming.** The theming docs cover the CSS classes, design tokens and presets (`primevue-4.5.5:apps/showcase/doc/tag/theming/index.vue`, `primevue-4.5.5:apps/showcase/doc/tag/theming/TailwindDoc.vue`, `primereact-10.9.9:components/doc/tag/theming/styleddoc.js`, `primereact-10.9.9:components/doc/tag/theming/tailwinddoc.js`). PrimeNG handles the same topics through the shared `themeDocs` entry (`primeng-21.1.9:apps/showcase/pages/tag/index.ts`). See section 8.
- **Services.** Tag needs no application-level service. PrimeNG injects its own `TagStyle` provider and a parent-instance token (`primeng-21.1.9:packages/primeng/src/tag/tag.ts` lines 31 and 85). PrimeVue's `BaseTag` provides `$pcTag` and `$parentInstance` (`primevue-4.5.5:packages/primevue/src/tag/BaseTag.vue` lines 15-18). PrimeReact reads `PrimeReactContext` (`primereact-10.9.9:components/lib/tag/Tag.js` line 10).

## 7. Accessibility

- No ARIA attribute or role is set in any of the three Tag sources. Attributes passed by the consumer reach the root element: PrimeNG `Bind` on the host and root through `ptms(['host', 'root'])` (`primeng-21.1.9:packages/primeng/src/tag/tag.ts` line 45); PrimeVue `ptmi('root')` with `inheritAttrs: false` (`primevue-4.5.5:packages/primevue/src/tag/Tag.vue` lines 2 and 18); PrimeReact `getOtherProps` spread onto the root (`primereact-10.9.9:components/lib/tag/Tag.js` line 40).
- PrimeVue's `ptmi` merges fallthrough attributes with the PT attributes for the given key (`primevue-4.5.5:packages/core/src/basecomponent/BaseComponent.vue`, lines 304-311).
- Keyboard: Tag has no interactive element and no keyboard handling. The accessibility docs say that focusability (`tabIndex`) and keyboard handlers must be added by the consumer when a tag is made interactive (`primeng-21.1.9:apps/showcase/doc/tag/accessibility-doc.ts`).
- The docs suggest `aria-live` on the root when tags change dynamically (`primevue-4.5.5:apps/showcase/doc/tag/AccessibilityDoc.vue`). The PrimeVue doc spells the attribute `tabindex`, while the PrimeNG and PrimeReact docs use `tabIndex`. The attribute is forwarded as written.
