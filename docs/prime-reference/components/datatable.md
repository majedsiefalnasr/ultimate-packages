# DataTable

**Category:** Data · **Frameworks:** PrimeNG 21.1.9 · PrimeVue 4.5.5 · PrimeReact 10.9.9

## 1. Summary

DataTable displays tabular data and is the largest component in all three libraries. Around a semantic `<table>` it adds client- or server-driven sorting (single and multi-column), per-column and global filtering on top of FilterService, row and cell selection, an embedded Paginator, lazy loading, vertical/horizontal/flex scrolling with frozen rows and columns, virtual scrolling through VirtualScroller/Scroller, row grouping (subheader, rowspan, expandable), row expansion, cell and row editing, CSV export, column resizing and reordering, row reordering, and state persistence to web storage. The architecture differs sharply. PrimeNG `Table` is template-driven: the app writes the `<tr>`/`<th>`/`<td>` markup in `header`/`body` templates and attaches behavior through directives. PrimeVue and PrimeReact are column-driven: the app declares `Column` children (optionally grouped by `ColumnGroup`/`Row`) and the component renders the markup (`primeng-21.1.9:packages/primeng/src/table/table.ts`, `primevue-4.5.5:packages/primevue/src/datatable/DataTable.vue`, `primereact-10.9.9:components/lib/datatable/DataTable.js`).

## 2. Names & status

- Canonical name: **DataTable**. PrimeNG names it **Table** (`p-table`, `TableModule`); PrimeVue and PrimeReact name it **DataTable**. All three list it first under **Data** (`primeng-21.1.9:apps/showcase/assets/data/menu.json`, `primevue-4.5.5:apps/showcase/assets/menu/menu.json`, `primereact-10.9.9:components/layout/menu.json`).
- Companion parts: PrimeVue and PrimeReact ship **Column**, **ColumnGroup**, and **Row** as separate entry points (`primevue/column`, `primevue/columngroup`, `primevue/row`; `primereact/column`, `primereact/columngroup`, `primereact/row`). PrimeNG has no column components. It exports about 25 directives/sub-components from `primeng/table` instead (`pSortableColumn`, `p-sortIcon`, `pSelectableRow`, `p-tableCheckbox`, `p-tableHeaderCheckbox`, `p-tableRadioButton`, `pRowToggler`, `pEditableColumn`, `p-cellEditor`, `pEditableRow`/`pInitEditableRow`/`pSaveEditableRow`/`pCancelEditableRow`, `pResizableColumn`, `pReorderableColumn`, `pReorderableRow`/`pReorderableRowHandle`, `pFrozenColumn`, `pRowGroupHeader`, `pContextMenuRow`, `pSelectableRowDblClick`, `p-columnFilter`, `p-columnFilterFormElement`). `p-columnFilter` also answers to `p-column-filter` and `p-columnfilter` (`primeng-21.1.9:packages/primeng/src/table/table.ts`).
- Deprecated:
  - PrimeNG `styleClass` (since v20.0.0) and `responsiveLayout` (since v20.0.0; it always behaves as `scroll`, and stack layouts need app CSS) (`primeng-21.1.9:packages/primeng/src/table/table.ts`).
  - PrimeVue slots `reorderindicatorupicon`/`reorderindicatordownicon` (since v4.0, replaced by `rowreorderindicatorupicon`/`rowreorderindicatordownicon`) (`primevue-4.5.5:packages/primevue/src/datatable/DataTable.d.ts`); Column slots `rowtogglericon` → `rowtoggleicon` and `nodetogglericon` → `nodetoggleicon` (since v4.0) (`primevue-4.5.5:packages/primevue/src/column/Column.d.ts`).
  - PrimeReact `responsiveLayout` (since 9.2.0) (`primereact-10.9.9:components/lib/datatable/datatable.d.ts`). The prop still drives the `p-datatable-responsive-stack`/`-scroll` root classes (`primereact-10.9.9:components/lib/datatable/DataTableBase.js`).

## 3. Per framework

**PrimeNG 21.1.9**

- Import: `TableModule` from `primeng/table` (`primeng-21.1.9:apps/showcase/doc/table/import-doc.ts`). Every component and directive is declared `standalone: false`, so the NgModule is the only entry point.
- Source `primeng-21.1.9:packages/primeng/src/table/table.ts` (about 6,600 lines; `Table`, `TableBody`, all directives, `ColumnFilter`, `TableService`); style `primeng-21.1.9:packages/primeng/src/table/style/tablestyle.ts` (imports `@primeuix/styles/datatable` and adds filter-overlay rules); types `primeng-21.1.9:packages/primeng/src/types/table/table.types.ts`; exports `primeng-21.1.9:packages/primeng/src/table/public_api.ts`.
- Filtering goes through the root-provided `FilterService` (`primeng-21.1.9:packages/primeng/src/api/filterservice.ts`). Supporting models: `FilterMatchMode`, `FilterOperator`, `FilterMetadata`, `SortMeta`, `TableState`, `LazyLoadMeta` (`primeng-21.1.9:packages/primeng/src/api/filtermatchmode.ts`, `primeng-21.1.9:packages/primeng/src/api/filteroperator.ts`, `primeng-21.1.9:packages/primeng/src/api/filtermetadata.ts`, `primeng-21.1.9:packages/primeng/src/api/sortmeta.ts`, `primeng-21.1.9:packages/primeng/src/api/tablestate.ts`, `primeng-21.1.9:packages/primeng/src/api/lazyloadmeta.ts`).
- Implements `BlockableUI`, so BlockUI can target it.

**PrimeVue 4.5.5**

- Import: `import DataTable from 'primevue/datatable'`, `import Column from 'primevue/column'`, plus `primevue/columngroup` and `primevue/row` for grouped headers (`primevue-4.5.5:apps/showcase/doc/datatable/ImportDoc.vue`).
- Source `primevue-4.5.5:packages/primevue/src/datatable/DataTable.vue`; props `primevue-4.5.5:packages/primevue/src/datatable/BaseDataTable.vue`; types `primevue-4.5.5:packages/primevue/src/datatable/DataTable.d.ts`; style `primevue-4.5.5:packages/primevue/src/datatable/style/DataTableStyle.js`. Internal parts: `TableHeader.vue`, `TableBody.vue`, `TableFooter.vue`, `HeaderCell.vue`, `FilterHeaderCell.vue`, `BodyRow.vue`, `BodyCell.vue`, `FooterCell.vue`, `ColumnFilter.vue`, `HeaderCheckbox.vue`, `RowCheckbox.vue`, `RowRadioButton.vue` (`primevue-4.5.5:packages/primevue/src/datatable/BodyRow.vue`, `primevue-4.5.5:packages/primevue/src/datatable/ColumnFilter.vue`).
- Column: `primevue-4.5.5:packages/primevue/src/column/Column.vue`, props `primevue-4.5.5:packages/primevue/src/column/BaseColumn.vue`, types `primevue-4.5.5:packages/primevue/src/column/Column.d.ts`. ColumnGroup: `primevue-4.5.5:packages/primevue/src/columngroup/ColumnGroup.vue` (prop `type`: `header` | `footer`; `primevue-4.5.5:packages/primevue/src/columngroup/BaseColumnGroup.vue`). Row: `primevue-4.5.5:packages/primevue/src/row/Row.vue` (renders nothing; it only registers itself with its parent group).
- FilterService, FilterMatchMode, FilterOperator come from `@primevue/core/api` (`primevue-4.5.5:packages/core/src/api/FilterService.js`).
- Nearly every piece of state supports `v-model`: `first`, `rows`, `sortField`, `sortOrder`, `multiSortMeta`, `filters`, `selection`, `contextMenuSelection`, `expandedRows`, `expandedRowGroups`, `editingRows`.

**PrimeReact 10.9.9**

- Import: `import { DataTable } from 'primereact/datatable'` and `import { Column } from 'primereact/column'` (`primereact-10.9.9:components/doc/datatable/importdoc.js`).
- Source `primereact-10.9.9:components/lib/datatable/DataTable.js`; defaults and CSS `primereact-10.9.9:components/lib/datatable/DataTableBase.js`; types `primereact-10.9.9:components/lib/datatable/datatable.d.ts`. Internal parts: `TableHeader.js`, `TableBody.js`, `TableFooter.js`, `HeaderCell.js`, `BodyRow.js`, `BodyCell.js`, `FooterCell.js`, `ColumnFilter.js`, `HeaderCheckbox.js`, `RowCheckbox.js`, `RowRadioButton.js`, `RowTogglerButton.js` (`primereact-10.9.9:components/lib/datatable/BodyCell.js`, `primereact-10.9.9:components/lib/datatable/ColumnFilter.js`).
- `Column` and `ColumnGroup` are empty function components (`() => {}`) whose props are read by DataTable (`primereact-10.9.9:components/lib/column/Column.js`, `primereact-10.9.9:components/lib/columngroup/ColumnGroup.js`); defaults in `primereact-10.9.9:components/lib/column/ColumnBase.js`; types `primereact-10.9.9:components/lib/column/column.d.ts`, `primereact-10.9.9:components/lib/columngroup/columngroup.d.ts`. `Row` renders a real `<tr>` (`primereact-10.9.9:components/lib/row/Row.js`, `primereact-10.9.9:components/lib/row/row.d.ts`).
- FilterService, FilterMatchMode, FilterOperator come from `primereact/api` (`primereact-10.9.9:components/lib/api/FilterService.js`, `primereact-10.9.9:components/lib/api/FilterMatchMode.js`).
- Most state is uncontrolled by default and becomes controlled when the matching callback is supplied (`onPage`, `onSort`, `onFilter`, and so on). `DataTableProps` is a union of selection-mode variants (single, cell-single, multiple, cell-multiple, radio, checkbox), so `selection` and `onSelectionChange` are typed per mode (`primereact-10.9.9:components/lib/datatable/datatable.d.ts`).

## 6. Usage guidance

- **Basic:** PrimeNG writes a `header` template with `<th>` cells and a `body` template with `<td>` cells. PrimeVue/PrimeReact list `<Column field header>` children (`primeng-21.1.9:apps/showcase/doc/table/basic-doc.ts`, `primevue-4.5.5:apps/showcase/doc/datatable/BasicDoc.vue`, `primereact-10.9.9:components/doc/datatable/basicdoc.js`). Dynamic columns: loop over a column array; in PrimeNG pass it as `[columns]` so export and the global-filter fallback can see it (`primeng-21.1.9:apps/showcase/doc/table/dynamic-doc.ts`, `primevue-4.5.5:apps/showcase/doc/datatable/DynamicColumnsDoc.vue`, `primereact-10.9.9:components/doc/datatable/dynamiccolumnsdoc.js`).
- **Sorting:** single column (`primeng-21.1.9:apps/showcase/doc/table/singlecolumnsort-doc.ts`, `primevue-4.5.5:apps/showcase/doc/datatable/sort/SingleColumnDoc.vue`, `primereact-10.9.9:components/doc/datatable/sort/singlecolumndoc.js`); `sortMode="multiple"` adds columns with the meta key (`primeng-21.1.9:apps/showcase/doc/table/multiplecolumnssort-doc.ts`, `primevue-4.5.5:apps/showcase/doc/datatable/sort/MultipleColumnsDoc.vue`, `primereact-10.9.9:components/doc/datatable/sort/multiplecolumnsdoc.js`); presort through `sortField`/`sortOrder`/`multiSortMeta` (`primeng-21.1.9:apps/showcase/doc/table/presort-doc.ts`, `primevue-4.5.5:apps/showcase/doc/datatable/sort/PresortDoc.vue`, `primereact-10.9.9:components/doc/datatable/sort/presortdoc.js`). A third click that clears the sort is a `removableSort` prop in Vue/React. PrimeNG has no such input; its demo builds it with `customSort` and a `sortFunction` handler (`primeng-21.1.9:apps/showcase/doc/table/removablesort-doc.ts`, `primevue-4.5.5:apps/showcase/doc/datatable/sort/RemovableSortDoc.vue`, `primereact-10.9.9:components/doc/datatable/sort/removablesortdoc.js`).
- **Filtering:** the filter model maps each field to `{ value, matchMode }` or, in menu mode, to `{ operator, constraints: [...] }`. `filterDisplay="row"` puts an input under each header. `menu` opens an overlay with match-mode dropdown, AND/OR operator, and add/remove rule buttons (default `maxConstraints` 2) (`primeng-21.1.9:apps/showcase/doc/table/filterbasic-doc.ts`, `primeng-21.1.9:apps/showcase/doc/table/filter-advanced-doc.ts`, `primevue-4.5.5:apps/showcase/doc/datatable/filter/BasicFilterDoc.vue`, `primevue-4.5.5:apps/showcase/doc/datatable/filter/AdvancedFilterDoc.vue`, `primereact-10.9.9:components/doc/datatable/filter/basicdoc.js`, `primereact-10.9.9:components/doc/datatable/filter/advanceddoc.js`). Column filters default to `startsWith`; PrimeNG `p-columnFilter` picks a default by `type` (text → `startsWith`, numeric → `equals`, date → `dateIs`). Global filtering defaults to `contains` and needs `globalFilterFields` (PrimeNG throws "Global filtering requires dynamic columns or globalFilterFields to be defined." when neither exists).
- **FilterService:** all three ship the same built-in constraint set (`startsWith`, `contains`, `notContains`, `endsWith`, `equals`, `notEquals`, `in`, `between`, `lt`, `lte`, `gt`, `gte`, `is`, `isNot`, `before`, `after`, `dateIs`, `dateIsNot`, `dateBefore`, `dateAfter`). Custom constraints are added with `register(name, fn)` and then offered via `matchModeOptions`/`filterMatchModeOptions` (`primeng-21.1.9:packages/primeng/src/api/filterservice.ts`, `primeng-21.1.9:apps/showcase/doc/filterservice/tableintegration-doc.ts`, `primevue-4.5.5:packages/core/src/api/FilterService.js`, `primereact-10.9.9:components/lib/api/FilterService.js`). PrimeNG's FilterService is an injectable `providedIn: 'root'`; PrimeVue/PrimeReact export a plain singleton object. PrimeReact additionally has `FilterMatchMode.CUSTOM` plus Column `filterFunction`, which DataTable registers as `custom_<field>` (`primereact-10.9.9:components/doc/datatable/filter/customdoc.js`, `primereact-10.9.9:components/lib/datatable/DataTable.js`).
- **Selection:** single, multiple (meta-key or toggle), radio-button column, and checkbox column with a header select-all (`primeng-21.1.9:apps/showcase/doc/table/singleselection-doc.ts`, `primeng-21.1.9:apps/showcase/doc/table/checkboxselection-doc.ts`, `primevue-4.5.5:apps/showcase/doc/datatable/rowselection/CheckboxRowSelectionDoc.vue`, `primevue-4.5.5:apps/showcase/doc/datatable/rowselection/RadioButtonRowSelectionDoc.vue`, `primereact-10.9.9:components/doc/datatable/rowselection/checkboxdoc.js`, `primereact-10.9.9:components/doc/datatable/rowselection/radiobuttondoc.js`). Set `dataKey` so selection compares by key rather than by deep equality. PrimeReact alone offers cell selection (`cellSelection`, optional `dragSelection`) (`primereact-10.9.9:components/doc/datatable/cellselection/singledoc.js`, `primereact-10.9.9:components/doc/datatable/cellselection/multipledoc.js`).
- **Pagination:** `paginator` + `rows` (+ `rowsPerPageOptions`); the embedded Paginator follows the Paginator record (`primeng-21.1.9:apps/showcase/doc/table/paginatorbasic-doc.ts`, `primevue-4.5.5:apps/showcase/doc/datatable/pagination/PaginationBasicDoc.vue`, `primereact-10.9.9:components/doc/datatable/paginator/basicdoc.js`). PrimeVue can hand the whole paginator to app markup through the `paginatorcontainer` slot (`primevue-4.5.5:apps/showcase/doc/datatable/pagination/PaginationHeadlessDoc.vue`).
- **Lazy:** enable `lazy`, set `totalRecords` from a count query, and fetch on events. PrimeNG funnels everything into `onLazyLoad`; PrimeVue/PrimeReact handle `page`/`sort`/`filter` separately (`primevue-4.5.5:apps/showcase/doc/datatable/LazyLoadDoc.vue`, `primereact-10.9.9:components/doc/datatable/lazyloaddoc.js`). The PrimeNG showcase has no stand-alone lazy page; lazy appears only with virtual scroll (`primeng-21.1.9:apps/showcase/doc/table/virtualscrolllazy-doc.ts`). The PrimeVue doc warns that checkbox select-all in lazy mode must be handled by the app.
- **Scrolling:** `scrollable` + `scrollHeight` for a fixed body with sticky header; `scrollHeight="flex"` fills a flex parent (the demos use a maximizable Dialog); frozen rows via `frozenValue`; frozen columns via `pFrozenColumn` (NG) or Column `frozen` (Vue/React) with `alignFrozen` left/right (`primeng-21.1.9:apps/showcase/doc/table/verticalscroll-doc.ts`, `primeng-21.1.9:apps/showcase/doc/table/flexiblescroll-doc.ts`, `primeng-21.1.9:apps/showcase/doc/table/frozencolumns-doc.ts`, `primeng-21.1.9:apps/showcase/doc/table/frozenrows-doc.ts`, `primevue-4.5.5:apps/showcase/doc/datatable/scroll/FrozenColumnsDoc.vue`, `primevue-4.5.5:apps/showcase/doc/datatable/scroll/FlexibleScrollDoc.vue`, `primereact-10.9.9:components/doc/datatable/scroll/frozencolumnsdoc.js`, `primereact-10.9.9:components/doc/datatable/scroll/flexibledoc.js`).
- **Virtual scroll:** requires `scrollable` + `scrollHeight` and a fixed row height (`itemSize`). Preloaded data or lazy chunks with a loading placeholder (`primeng-21.1.9:apps/showcase/doc/table/virtualscroll-doc.ts`, `primevue-4.5.5:apps/showcase/doc/datatable/virtualscroll/PreloadVirtualScrollDoc.vue`, `primevue-4.5.5:apps/showcase/doc/datatable/virtualscroll/LazyVirtualScrollDoc.vue`, `primereact-10.9.9:components/doc/datatable/virtualscroll/preloaddoc.js`, `primereact-10.9.9:components/doc/datatable/virtualscroll/lazydoc.js`).
- **Row grouping:** sort by the group field first, then `rowGroupMode="subheader"` with group header/footer templates, `rowspan` to merge cells, or expandable subheaders (`primeng-21.1.9:apps/showcase/doc/table/subheadergrouping-doc.ts`, `primeng-21.1.9:apps/showcase/doc/table/rowspangrouping-doc.ts`, `primeng-21.1.9:apps/showcase/doc/table/expandablerowgroup-doc.ts`, `primevue-4.5.5:apps/showcase/doc/datatable/rowgroup/SubHeaderRowGroupDoc.vue`, `primevue-4.5.5:apps/showcase/doc/datatable/rowgroup/ExpandableRowGroupDoc.vue`, `primereact-10.9.9:components/doc/datatable/rowgroup/subheaderdoc.js`, `primereact-10.9.9:components/doc/datatable/rowgroup/expandabledoc.js`).
- **Row expansion:** needs `dataKey`; an expander column toggles a full-width detail row (often a nested table) (`primeng-21.1.9:apps/showcase/doc/table/rowexpansion-doc.ts`, `primevue-4.5.5:apps/showcase/doc/datatable/RowExpansionDoc.vue`, `primereact-10.9.9:components/doc/datatable/rowexpansiondoc.js`).
- **Editing:** cell mode edits one cell on click and commits on Enter/blur, cancels on Escape; row mode toggles a whole row with init/save/cancel buttons and needs `dataKey` (`primeng-21.1.9:apps/showcase/doc/table/celledit-doc.ts`, `primeng-21.1.9:apps/showcase/doc/table/rowedit-doc.ts`, `primevue-4.5.5:apps/showcase/doc/datatable/edit/CellEditDoc.vue`, `primevue-4.5.5:apps/showcase/doc/datatable/edit/RowEditDoc.vue`, `primereact-10.9.9:components/doc/datatable/edit/celleditdoc.js`, `primereact-10.9.9:components/doc/datatable/edit/roweditdoc.js`). Editors are ordinary inputs (InputText, InputNumber, Select). The CRUD sample combines this with Dialog and Toolbar (`primeng-21.1.9:apps/showcase/doc/table/products-doc.ts`, `primevue-4.5.5:apps/showcase/doc/datatable/samples/ProductsDoc.vue`, `primereact-10.9.9:components/doc/datatable/samples/productsdoc.js`).

## 7. Accessibility

- All three docs describe the same contract: native table semantics, `aria-sort` on sortable headers, `aria-selected` on selectable rows, a row toggler button with `aria-expanded`/`aria-controls`, labelled row-editor buttons, and a filter menu button with `aria-haspopup`/`aria-expanded`/`aria-controls` opening a `role="dialog"` overlay. Keyboard: Tab/Enter/Space on sortable headers; Tab/Escape/Enter inside the filter menu; for selection, Tab, Up/Down, Home/End, Enter, Space, Shift+arrows, and Ctrl/Cmd+A (`primeng-21.1.9:apps/showcase/doc/table/accessibility-doc.ts`, `primevue-4.5.5:apps/showcase/doc/datatable/AccessibilityDoc.vue`, `primereact-10.9.9:components/doc/datatable/accessibilitydoc.js`). An accessible name for the table is passed through `tableProps` (Vue) or the table attributes the app writes (NG).
- PrimeVue source implements the contract: `role` table/rowgroup/row/columnheader/cell, `aria-sort`, `aria-selected` when `selectionMode` is set, roving `tabindex` on rows and sortable headers, toggler `aria-expanded` + `aria-controls` + label, labelled checkboxes and editor buttons (`primevue-4.5.5:packages/primevue/src/datatable/BodyRow.vue`, `primevue-4.5.5:packages/primevue/src/datatable/BodyCell.vue`, `primevue-4.5.5:packages/primevue/src/datatable/HeaderCell.vue`).
- PrimeReact source also implements it: `aria-selected` on rows, `aria-sort` on headers, toggler `aria-expanded` and an expand/collapse label (`primereact-10.9.9:components/lib/datatable/BodyRow.js`, `primereact-10.9.9:components/lib/datatable/HeaderCell.js`, `primereact-10.9.9:components/lib/datatable/BodyCell.js`, `primereact-10.9.9:components/lib/datatable/RowTogglerButton.js`).
- Doc/source mismatch (PrimeNG): because rows, toggler, and editor buttons are app markup, `table.ts` adds no `aria-selected` to rows and no `aria-expanded`/`aria-controls` to `pRowToggler`. Those attributes exist only if the app writes them. The library does add `aria-sort` and `tabindex` through `pSortableColumn`, `tabindex` and keyboard handling through `pSelectableRow`, translated labels on `p-tableCheckbox`/`p-tableHeaderCheckbox`, and the filter button/overlay ARIA in `p-columnFilter`. The PrimeNG accessibility doc also mentions a Column `filterInputProps`, which is a PrimeVue concept with no PrimeNG equivalent (`primeng-21.1.9:packages/primeng/src/table/table.ts`, `primeng-21.1.9:apps/showcase/doc/table/accessibility-doc.ts`).
- None of the three sets `aria-busy` while `loading`.

## 9. Relationships

- Embeds **Paginator** (`primeng/paginator`, `primevue/paginator`, `../paginator/Paginator`) and forwards its props and icon templates.
- Virtual scrolling delegates to **VirtualScroller** (PrimeNG `Scroller`).
- Filter UI: the menu overlay always composes **Select** (PrimeReact: Dropdown) for match mode/operator and **Button** for add/remove/clear/apply. PrimeNG `p-columnFilter` also renders its own value editors (**InputText**, **InputNumber**, **DatePicker**, **Checkbox**) and imports SelectButton. PrimeReact renders a default **InputText**. PrimeVue renders no value editor; the app supplies it through the Column `filter` slot.
- Selection columns use **Checkbox** and **RadioButton**; multi-sort uses **Badge**.
- Row context menu pairs with **ContextMenu**. Column toggling uses **MultiSelect**. Loading demos use **Skeleton**; CRUD samples use **Dialog**, **Toolbar**, **Toast**, **Tag**, **Rating**.
- PrimeNG: works with **BlockUI** via `BlockableUI`.
- Close relatives: **TreeTable** (hierarchical sibling with a parallel API; PrimeVue/PrimeReact reuse `Column`/`ColumnGroup`/`Row` for it, hence the `nodeToggleButton`/`pcNodeCheckbox` keys in PrimeVue Column PT), **DataView** (non-tabular collection with the same paging/sorting model), and **FilterService** (shared with DataView and others).

## 11. Framework differences

| Aspect                    | PrimeNG                                                       | PrimeVue                                             | PrimeReact                                                       |
| ------------------------- | ------------------------------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------------------- |
| Name / entry              | `Table` / `TableModule` (NgModule only)                       | `DataTable` + `Column`, `ColumnGroup`, `Row`         | `DataTable` + `Column`, `ColumnGroup`, `Row`                     |
| Authoring model           | Templates own `<tr>/<th>/<td>`; behavior via directives       | Declarative `Column` children; library renders cells | Declarative `Column` children; library renders cells             |

| Lazy event                | Single `onLazyLoad`                                           | Separate `page`/`sort`/`filter`                      | Separate `onPage`/`onSort`/`onFilter`                            |

| Removable sort            | Via `customSort` in app code                                  | `removableSort`                                      | `removableSort`                                                  |
