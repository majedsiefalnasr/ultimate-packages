# FocusTrap

**Category:** Misc · **Frameworks:** PrimeNG 21.1.9 · PrimeVue 4.5.5 · PrimeReact 10.9.9

## 1. Summary

FocusTrap keeps keyboard focus inside one DOM container while the user tabs. It inserts two visually hidden, focusable sentinel elements: one before the container's content and one after it. When a sentinel receives focus, the trap moves focus to the first or last focusable element inside the container. PrimeNG ships it as the attribute directive `[pFocusTrap]`, PrimeVue as the directive `v-focustrap`, and PrimeReact as a wrapper component `<FocusTrap>` with no showcase documentation. The trap is not a modal on its own. It has no backdrop, no Escape handling and no focus restoration. Host components such as Dialog, Drawer and ConfirmPopup add those behaviours (`primeng-21.1.9:packages/primeng/src/focustrap/focustrap.ts`, `primevue-4.5.5:packages/primevue/src/focustrap/FocusTrap.js`, `primereact-10.9.9:components/lib/focustrap/FocusTrap.js`).

## 4. Anatomy

FocusTrap has no sub-components, slots or named template parts. The directive or component adds two sentinel elements, and that is the only DOM it creates:

- Each sentinel is a `<span>` with class `p-hidden-accessible p-hidden-focusable`, `tabindex` 0, `role="presentation"`, `aria-hidden="true"`, and the data attributes `data-p-hidden-accessible` and `data-p-hidden-focusable`. The `data-pc-section` values are `firstfocusableelement` and `lastfocusableelement` (`primeng-21.1.9:packages/primeng/src/focustrap/focustrap.ts`, lines 58-80; `primevue-4.5.5:packages/primevue/src/focustrap/FocusTrap.js`, lines 96-123; `primereact-10.9.9:components/lib/focustrap/FocusTrap.js`, lines 88-120).
- Placement: PrimeNG and PrimeVue prepend the first sentinel and append the last to the host element they are applied to (`primeng-21.1.9:packages/primeng/src/focustrap/focustrap.ts`, lines 79-80; `primevue-4.5.5:packages/primevue/src/focustrap/FocusTrap.js`, lines 122-123). PrimeReact returns a fragment that places the first sentinel, `props.children` and the last sentinel as siblings. The trap container is therefore the DOM parent of the component, not a wrapper it creates (`primereact-10.9.9:components/lib/focustrap/FocusTrap.js`, lines 116-120 and line 38 `getTarget`).
- PrimeVue also sets the attribute `data-pd-focustrap` on the host element (`primevue-4.5.5:packages/primevue/src/focustrap/FocusTrap.js`, line 15).

## 5. API highlights

**PrimeNG — `FocusTrap` directive** (`primeng-21.1.9:packages/primeng/src/focustrap/focustrap.ts`)

- Input `pFocusTrapDisabled: boolean`, default `false`, `booleanAttribute` transform (line 19). When `true`, the sentinels are removed. When it changes back to `false`, the sentinels are recreated (lines 35-43).
- Inherited from `BaseComponent`: `dt`, `pt`, `ptOptions`, `unstyled` (catalog module `focustrap`, component `FocusTrap`; `docs/prime-reference/catalog/primeng.json`).
- Public fields: `platformId`, `document`, `firstHiddenFocusableElement`, `lastHiddenFocusableElement` (lines 21-25).
- Public methods (no `private` modifier): `onInit`, `onChanges`, `removeHiddenFocusableElements`, `getComputedSelector` (line 54), `createHiddenFocusableElements`, `onFirstHiddenElementFocus` and `onLastHiddenElementFocus`. No method is documented as API.
- Outputs: none. There is no `@Output`, and no event is emitted.
- Catalog vs source: the catalog lists `pFocusTrapDisabled` as `boolean` with default `"false"`, which matches the source.
- `getComputedSelector` is never called. The two focus handlers use the literal `:not(.p-hidden-focusable)` instead, so the helper is dead code (`primeng-21.1.9:packages/primeng/src/focustrap/focustrap.ts`, lines 54-56 and 83-98).

**PrimeVue — `v-focustrap` directive value** (`FocusTrapOptions`, `primevue-4.5.5:packages/primevue/src/focustrap/FocusTrap.d.ts`)

- `disabled?: boolean`, documented default `false`. Read in `mounted` and `updated` (`primevue-4.5.5:packages/primevue/src/focustrap/FocusTrap.js`, lines 7-9 and 20-22).
- `autoFocus?: boolean`, documented default `true` (`FocusTrap.d.ts`, line 28). The runtime destructures `autoFocus = false` (`FocusTrap.js`, line 72). The `.d.ts` and the catalog (`docs/prime-reference/catalog/primevue.json`, interface `FocusTrapOptions`) disagree with the code, and the runtime default wins.
- `dt?: DesignToken<any>` and `ptOptions?` are declared, but `FocusTrap.js` never reads them (see §8).
- `pt?: PassThrough<FocusTrapDirectivePassThroughOptions>` is declared. The runtime reads no pass-through section except lifecycle hooks (see §8).
- Runtime options that are read but not declared in the typings or the catalog: `tabIndex` (default `0`, `FocusTrap.js` line 97), `autoFocusSelector`, `firstFocusableSelector`, `lastFocusableSelector` (default `''`, lines 72 and 97), `onFocusIn` and `onFocusOut` (line 32). The catalog therefore omits these members.
- Instance methods on the element, exposed as `el.$focustrap`: `autoFocus(options)`, which calls `autoElementFocus` with `autoFocus: true` (`FocusTrap.js`, lines 68-70). PrimeVue's `ColumnFilter.vue` calls `this.overlay?.$focustrap?.autoFocus()` after the overlay enter transition (`primevue-4.5.5:packages/primevue/src/datatable/ColumnFilter.vue`, line 550).
- Typed binding: `FocusTrapDirectiveBinding` (`FocusTrap.d.ts`). No events are emitted.
- Deprecated members: none.

**PrimeReact — `<FocusTrap>` component** (`primereact-10.9.9:components/lib/focustrap/FocusTrap.js`)

- Props read at mount: `disabled` (read once, line 32), `autoFocus` (default falsy, line 51), `autoFocusSelector` and `firstFocusableSelector` (line 51). `tabIndex` defaults to `0` when the sentinels are created (line 89). `children` is rendered between the sentinels (line 118).
- `lastFocusableSelector` is never read (verified by grep of `FocusTrap.js`), and `$_pfocustrap_focusableselector` is never assigned, so the focus handlers use the default selector.
- Imperative handle through `forwardRef` and `useImperativeHandle` (lines 25-29): `props`, `getInk()` (returns the first sentinel, not an ink element), and `getTarget()` (returns the container, which is the parent of the first sentinel).
- No event props and no `onFocusIn` or `onFocusOut`.
- Typings: the package declares `types: ./focustrap.d.ts`, but no `focustrap.d.ts` exists under `components/lib/focustrap/` or anywhere in the PrimeReact archive. The package.json entry dangles.
- Catalog: no FocusTrap entry in `primereact.json`, and no `focustrap` key in `components/doc/common/apidoc/index.json`.
- Deprecated members: none.

## 6. Usage guidance

- **Import / registration.** PrimeNG imports `FocusTrapModule` (or the standalone `FocusTrap`) into the component (`primeng-21.1.9:apps/showcase/doc/focustrap/import-doc.ts`). PrimeVue registers the directive globally with `app.directive('focustrap', FocusTrap)` (`primevue-4.5.5:apps/showcase/doc/focustrap/ImportDoc.vue`). PrimeReact has no showcase import section.
- **Basic (PrimeNG).** The doc says the directive is applied to a container element. The demo puts `pFocusTrap` on a `div` that wraps a name input with `[pAutoFocus]="true"`, an email input, a checkbox and a submit button (`primeng-21.1.9:apps/showcase/doc/focustrap/basic-doc.ts`). FocusTrap itself does not move focus on mount. The initial focus comes from the AutoFocus directive on the name input.
- **Basic (PrimeVue).** The doc says the directive is enabled with the `v-` prefix. The demo applies `v-focustrap` to a `div` that wraps the same four controls. The first `InputText` uses the native `autofocus` attribute, which the directive picks up on mount (`primevue-4.5.5:apps/showcase/doc/focustrap/BasicDoc.vue`). The Options and Composition code tabs show the same markup.
- **Initial focus, source rule (PrimeVue).** On mount, the directive focuses the first element with the `autofocus` attribute inside the host. It does this regardless of the `autoFocus` option. The `autoFocus` option only adds a fallback to the first focusable element (`primevue-4.5.5:packages/primevue/src/focustrap/FocusTrap.js`, lines 71-76).
- **Initial focus, source rule (PrimeReact).** `autoFocus` enables a fallback to the first focusable element. The `[autofocus]` and `[data-pc-autofocus='true']` selectors are checked first, as in `setAutoFocus` (`primereact-10.9.9:components/lib/focustrap/FocusTrap.js`, lines 50-60).
- **Dialog-style use.** The hosts show the intended patterns. PrimeVue Dialog passes `disabled: !modal` (`primevue-4.5.5:packages/primevue/src/dialog/Dialog.vue`, line 5). PrimeNG Dialog binds `[pFocusTrapDisabled]="focusTrap === false"` and defaults `focusTrap` to `true` (`primeng-21.1.9:packages/primeng/src/dialog/dialog.ts`, lines 77-78 and 303). PrimeReact Dialog wraps its content in `<FocusTrap autoFocus={props.focusOnShow}>` (`primereact-10.9.9:components/lib/dialog/Dialog.js`, line 705).
- **Gallery-style use.** PrimeNG Galleria disables the trap unless the gallery is fullscreen, with `[pFocusTrapDisabled]="!fullScreen"` (`primeng-21.1.9:packages/primeng/src/galleria/galleria.ts`, lines 86-87).
- **Disable at runtime (PrimeNG).** Changing `pFocusTrapDisabled` removes or recreates the sentinels, so the trap can be turned off and on (`primeng-21.1.9:packages/primeng/src/focustrap/focustrap.ts`, lines 35-43).
- **Disable at runtime (PrimeVue, source-derived).** Disabling after mount only disconnects the observer and the focusin/focusout listeners. The sentinels stay in place with their focus handlers, and re-enabling does not recreate them. Use `v-if` on the directive host if the trap must be fully removed (`primevue-4.5.5:packages/primevue/src/focustrap/FocusTrap.js`, lines 19-22 and 63-67).
- **Disable at runtime (PrimeReact, source-derived).** `disabled` is read only at mount. The sentinels are always rendered. The focus handlers fall back to the parent container when `targetRef` is null, so a disabled instance can still redirect focus. The source does not show a supported way to turn the trap off after mount (`primereact-10.9.9:components/lib/focustrap/FocusTrap.js`, lines 31-36 and 66-86).
- **Limits.** The directive does not stop mouse focus, and it has no overlay or mask. Modal behaviour comes from the host (for example PrimeVue `Dialog` `role="dialog"` and `aria-modal`).

## 7. Accessibility

- **Roles and attributes set by FocusTrap.** The sentinels carry `role="presentation"` and `aria-hidden="true"`, so assistive technology ignores them. The host receives no role from FocusTrap; the hosts set their own roles (`primeng-21.1.9:packages/primeng/src/focustrap/focustrap.ts`, lines 58-70; `primevue-4.5.5:packages/primevue/src/focustrap/FocusTrap.js`, lines 96-106; `primereact-10.9.9:components/lib/focustrap/FocusTrap.js`, lines 96-106). Host roles include PrimeVue `Dialog` with `role="dialog"` and `aria-modal` (`primevue-4.5.5:packages/primevue/src/dialog/Dialog.vue`, line 5), PrimeVue `ConfirmPopup` with `role="alertdialog"` (`primevue-4.5.5:packages/primevue/src/confirmpopup/ConfirmPopup.vue`, line 4), and PrimeNG `Drawer` with `role="complementary"` (`primeng-21.1.9:packages/primeng/src/drawer/drawer.ts`, line 64).
- **Visual hiding.** The sentinels use the `p-hidden-accessible` class, which hides them visually. The PrimeNG rule is in `basestyle.ts` (lines 8-17). The PrimeVue rule in `BaseStyle.js` (lines 7-19) also sets `opacity: 0`, `pointer-events: none` and `white-space: nowrap`. The PrimeReact rule is in `ComponentBase.js` baseStyle (line 6), loaded by `useHandleStyle` (lines 604-628). `FocusTrap.js` does not call `useHandleStyle`, so the rule is present only if the page loads base styles through another component. This was not verified in a browser (see §12 gaps).
- **Keyboard.** The trap works through Tab and Shift+Tab: focus that reaches a sentinel is moved to the first or last focusable element inside the container. The sentinels are focusable (`tabindex` 0). FocusTrap handles no other key. It does not handle Escape, and it does not handle arrow keys.
- **Escape key is host-owned.** PrimeNG Drawer closes on Escape in its own `onKeyDown` handler (`primeng-21.1.9:packages/primeng/src/drawer/drawer.ts`, lines 362-366). PrimeVue Drawer does the same when `closeOnEscape` is set (`primevue-4.5.5:packages/primevue/src/drawer/Drawer.vue`, line 170). PrimeReact Dialog uses a global Escape hook gated by `closable` and `closeOnEscape` (`primereact-10.9.9:components/lib/dialog/Dialog.js`, lines 41 and 56-60).
- **Initial focus.** The first focus target depends on the framework. PrimeNG focuses nothing by itself; the AutoFocus directive or a native `autofocus` attribute is needed. PrimeVue focuses the first `[autofocus]` element, or the first focusable element when `autoFocus` is set. PrimeReact focuses the first focusable element when `autoFocus` is set, after checking `[autofocus]` and `[data-pc-autofocus='true']`.
- **Focus restoration.** None of the three implementations records the element that had focus before the trap was activated, and none restores it on release. Return-focus behaviour is up to the host. (The source has no `activeElement` capture; the only `activeElement` use is the PrimeVue MutationObserver guard, `primevue-4.5.5:packages/primevue/src/focustrap/FocusTrap.js`, line 36.)
- **Focus loss on DOM change (PrimeVue only).** A MutationObserver watches the host's child list. When focus is outside the host after a child change, it moves focus to the next focusable element at or after the mutation's `nextSibling` (`primevue-4.5.5:packages/primevue/src/focustrap/FocusTrap.js`, lines 31-46). PrimeNG and PrimeReact have no equivalent.
- **Accessibility documentation.** No FocusTrap accessibility page exists in any framework. The PrimeNG doc folder contains only `basic-doc.ts` and `import-doc.ts`, and the PrimeVue doc folder contains only `BasicDoc.vue` and `ImportDoc.vue` (`primeng-21.1.9:apps/showcase/doc/focustrap/basic-doc.ts`, `primevue-4.5.5:apps/showcase/doc/focustrap/BasicDoc.vue`). This section relies on source only.
- **Reduced motion.** N/A — FocusTrap has no animation.

## 8. Theming

- **Style classes.** None are exported. PrimeNG's `FocusTrap` has no style class enum, and the catalog lists no `style` block for `focustrap`. The two classes `p-hidden-accessible p-hidden-focusable` are hard-coded (`primeng-21.1.9:packages/primeng/src/focustrap/focustrap.ts`, line 63). PrimeVue exports `FocusTrapClasses` as an empty enum (`primevue-4.5.5:packages/primevue/src/focustrap/style/FocusTrapStyle.d.ts`), and the catalog interface `FocusTrapStyle` has no members (`docs/prime-reference/catalog/primevue.json`, module `focustrapstyle`). PrimeReact's `styles` string is empty (`primereact-10.9.9:components/lib/focustrap/FocusTrapBase.js`, line 4).
- **Pass-through sections.** PrimeVue declares three keys: `root`, `firstFocusableElement`, `lastFocusableElement` (`primevue-4.5.5:packages/primevue/src/focustrap/FocusTrap.d.ts`). The runtime never calls `ptm()` (no `ptm`, `ptmi`, `cx` or `sx` calls in `FocusTrap.js`), so these keys have no effect on the DOM. The global key `directives.focustrap` is typed in `primevue-4.5.5:packages/primevue/src/config/Config.d.ts` (line 301) and matches the runtime directive name. Only the `hooks` pass-through key is read, through `_hook` in BaseDirective (`primevue-4.5.5:packages/core/src/basedirective/BaseDirective.js`, lines 149-150). PrimeNG declares no pass-through sections; the inherited `pt`, `ptOptions` and `unstyled` inputs have no template to target (`primeng-21.1.9:packages/primeng/src/focustrap/focustrap.ts`). PrimeReact calls `ptm` in the destructuring at line 21 but never uses it (`primereact-10.9.9:components/lib/focustrap/FocusTrap.js`).
- **Design tokens.** N/A for all three frameworks. `@primeuix/themes-2.0.3:types/index.d.ts` contains no focustrap entry, and `@primeuix/themes-2.0.3:tokens` has no focustrap token group. PrimeVue's `dt` is typed in the directive options but not read at runtime, apart from the BaseDirective scoped-theme hook, which only runs when a preset is set (`primevue-4.5.5:packages/core/src/basedirective/BaseDirective.js`, lines 127-132 and 184). PrimeNG's inherited `dt` input triggers scoped theme loading in `BaseComponent` (`primeng-21.1.9:packages/primeng/src/basecomponent/basecomponent.ts`, lines 166-172), but `FocusTrap` defines no component style, so that path is a no-op (inferred from the code, not run).
- **`@primeuix/styles` module.** N/A — `@primeuix/styles-2.0.3:dist/` has no focustrap folder, and `@primeuix/styles-2.0.3:dist/base/index.mjs` has no `hidden-accessible` rule. The PrimeNG and PrimeVue base rules come from their own base modules instead (`primeng-21.1.9:packages/primeng/src/base/style/basestyle.ts`; `primevue-4.5.5:packages/core/src/base/style/BaseStyle.js`).
- **Own CSS.** PrimeVue's style module has no CSS. Its `BaseStyle` sub-module carries the base hidden-accessible rule, and it is loaded through `_loadCoreStyles` (`primevue-4.5.5:packages/core/src/basedirective/BaseDirective.js`, lines 85-91).
- **Hidden-focusable selector.** No CSS rule targets `.p-hidden-focusable` in any archive. The class appears only as a string in the JavaScript that builds the sentinels, and the focus selectors exclude it with `:not(.p-hidden-focusable)`.

- **Overlay family.** Dialog, Drawer, Popover, ConfirmPopup, Image and Galleria all use FocusTrap in addition to their own overlay logic. Their records (dialog, drawer, popover, confirmpopup, galleria, image) are in the overlay and media worktrees.
- **Related (Misc):** **AutoFocus** is the directive that does what the PrimeNG FocusTrap does not: it sets initial focus (`primeng-21.1.9:packages/primeng/src/autofocus/autofocus.ts`, lines 11 and 19). The PrimeNG demo combines the two. **StyleClass** and **AnimateOnScroll** are other Misc directives. They add and remove classes and do not manage focus (`primevue-4.5.5:packages/primevue/src/animateonscroll/AnimateOnScroll.js`).
- **Directive family (PrimeVue).** FocusTrap extends the same `BaseDirective` as the other PrimeVue directives (`primevue-4.5.5:packages/core/src/basedirective/BaseDirective.js`).
- **Alias chain:** none. `pFocusTrap`, `v-focustrap` and `<FocusTrap>` are the same concept in three frameworks, not aliases of one another.

## 10. Dependencies

- **PrimeNG internal:** `primeng/basecomponent` (`BaseComponent`), `@primeuix/utils` (`createElement`, `focus`, `getFirstFocusableElement`, `getLastFocusableElement`) (`primeng-21.1.9:packages/primeng/src/focustrap/focustrap.ts`, line 3), and `@angular/common` (`DOCUMENT`, `isPlatformBrowser`). It uses `@angular/core` for the directive, input, `PLATFORM_ID` and NgModule. The directive does not import a style module.
- **PrimeVue internal:** `@primeuix/utils/dom` (`createElement`, `focus`, `getFirstFocusableElement`, `getLastFocusableElement`, `isFocusableElement`) and `@primeuix/utils/object` (`isNotEmpty`) (`primevue-4.5.5:packages/primevue/src/focustrap/FocusTrap.js`, lines 1-2). `@primevue/core/basedirective` (`BaseDirective`) and `primevue/focustrap/style` (`BaseFocusTrap.js`). `@primevue/core/base/style` (`BaseStyle`) for the style module (`primevue-4.5.5:packages/primevue/src/focustrap/style/FocusTrapStyle.js`).
- **PrimeReact internal:** `../api/Api` (`PrimeReactContext`), `../hooks/Hooks` (`useMountEffect`, `useStyle`), `../utils/Utils` (`DomHandler`, `ObjectUtils`) and `../componentbase/ComponentBase` (`primereact-10.9.9:components/lib/focustrap/FocusTrap.js`, lines 1-5; `FocusTrapBase.js`, lines 1-2).
- **External npm:** PrimeNG needs `@angular/common`, `@angular/core` and `@primeuix/utils` (peer and catalog dependencies in `primeng-21.1.9:packages/primeng/package.json`). PrimeVue needs `vue` for its types (`primevue-4.5.5:packages/primevue/src/focustrap/FocusTrap.d.ts`, line 13) and `@primeuix/utils`. PrimeReact needs `react`; its rollup externals list does not add a focus-specific package (`primereact-10.9.9:rollup.config.js`, line 115).
- **Browser APIs:** `MutationObserver` (PrimeVue only), `focusin` and `focusout` listeners (PrimeVue), `document.activeElement` (PrimeVue), and `HTMLElement.focus` in all three.
