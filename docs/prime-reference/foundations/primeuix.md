# @primeuix foundations

Reference note for the five pinned `@primeuix` packages that PrimeNG and PrimeVue build on. It records what each package ships and how the three pinned framework baselines consume it. Every fact is taken from the pinned archives listed in `docs/architecture/checksums.json`; citations use the form `<package>-<version>:<path inside the package>`.

| Package            | Version | Role in one line                                                                |
| ------------------ | ------- | ------------------------------------------------------------------------------- |
| `@primeuix/utils`  | 0.7.2   | Framework-agnostic helpers: DOM, object, class names, event bus, z-index, uuid. |
| `@primeuix/styled` | 0.7.4   | Theming engine: design tokens to CSS variables, color schemes, CSS layers.      |
| `@primeuix/themes` | 2.0.3   | Token presets Aura, Lara, Material, Nora plus token types and metadata.         |
| `@primeuix/styles` | 2.0.3   | Structural CSS per component, written against `dt('…')` token references.       |
| `@primeuix/motion` | 0.0.10  | Enter/leave transition and animation driver for DOM elements.                   |

Dependency chain inside the family (`dependencies` in each `package.json`):

- `@primeuix/styles` and `@primeuix/themes` depend on `@primeuix/styled` `^0.7.4`.
- `@primeuix/styled` depends on `@primeuix/utils` `^0.6.1`; `@primeuix/motion` depends on `@primeuix/utils` `^0.6.3`. Both ranges exclude the pinned utils 0.7.2, so a consumer that pins utils 0.7.x gets a second utils copy for styled and motion unless its package manager overrides the range. (`@primeuix/styled-0.7.4:package.json`, `@primeuix/motion-0.0.10:package.json`)
- `@primeuix/utils` has no dependencies. (`@primeuix/utils-0.7.2:package.json`)

All five packages are ESM only (`main`/`module` point to `dist/index.mjs`), declare `"sideEffects": false`, and are MIT licensed.

## @primeuix/styled 0.7.4

**Purpose.** The theming engine. It turns a preset (a nested object of design tokens) into CSS custom properties, resolves `{token.path}` references, scopes dark-mode values to a configurable selector, optionally wraps output in a CSS cascade layer, and keeps a registry of which style sheets are loaded.

**Entry point.** `.` only (`@primeuix/styled-0.7.4:package.json`). Everything below is exported from `@primeuix/styled-0.7.4:dist/index.d.mts`.

### Options and defaults

`ThemeOptions` has three documented fields (`@primeuix/styled-0.7.4:dist/index.d.mts`); `Theme.defaults` holds their runtime defaults (`@primeuix/styled-0.7.4:dist/index.mjs`):

| Option             | Type                                           | Default    | Effect                                                                                                                                                                                                                                                                                               |
| ------------------ | ---------------------------------------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prefix`           | `string`                                       | `'p'`      | Leading segment of every variable, e.g. `--p-button-border-radius`.                                                                                                                                                                                                                                  |
| `darkModeSelector` | `string`                                       | `'system'` | Where dark values apply. `'system'` → `@media (prefers-color-scheme: dark)`; `.class` → that class; `[attr]` → `:root[attr],:host[attr]`; `@media …` → that query; anything else is used verbatim (a `[CSS]` placeholder is replaced by the declarations). `'none'` or `false` disables dark output. |
| `cssLayer`         | `boolean \| { name?: string; order?: string }` | `false`    | When set, generated CSS is wrapped in `@layer <name>` (default name `primeui`); `getLayerOrder` emits `@layer <order \| name \| 'primeui'>`.                                                                                                                                                         |

The engine also reads an undocumented `transform` option: with `transform: 'strict'` it skips variable generation and `dt()` returns raw token values (`@primeuix/styled-0.7.4:dist/index.mjs`).

Variable defaults: prefix `p`, selector `:root,:host`, and an `excludedKeyRegex` that drops the structural keys `primitive|semantic|components|directives|variables|colorscheme|light|dark|common|root|states|extend|css` from variable names. So `semantic.colorScheme.light.primary.color` becomes `--p-primary-color`, and `components.button.root.borderRadius` becomes `--p-button-border-radius`.

### How CSS is produced

1. `getCommon` splits the preset into `primitive`, `semantic` (minus `colorScheme`), `semantic.colorScheme.light`, `semantic.colorScheme.dark`, plus the same parts of `extend`. Each part goes through `toVariables`; light parts are emitted under `:root,:host`, dark parts under the resolved `darkModeSelector`. It returns `primitive`, `semantic`, `global` (`css` extensions) and `style` blocks.
2. `getPresetC` / `getPresetD` do the same for one entry of `components` / `directives`, honouring the entry's own `colorScheme`, `extend` and `css`.
3. Token references written as `{path.to.token}` become `var(--p-path-to-token)`; arithmetic expressions are wrapped in `calc(...)`; a reference that resolves to a light/dark pair becomes `light-dark(a,b)` in computed values. Circular references log `Circular reference detected at …` and resolve to `undefined`.
4. `getStyleSheet` / `getCommonStyleSheet` return `<style type="text/css" data-primevue-style-id="<name>-variables" …>` markup for server rendering; the attribute name is `data-primevue-style-id` for every consumer, PrimeNG included.

(`@primeuix/styled-0.7.4:dist/index.mjs`)

### Presets

There are exactly four presets: **Aura, Lara, Material, Nora** (`@primeuix/themes-2.0.3:dist/`). Each preset object has `primitive`, `semantic`, and `components` (88 entries). Aura additionally has a top-level `css` string (selection and hover rules for option rows across list components) and component-level `css` for `datatable`, `tree`, `treetable`; Material has component-level `css` on 31 components; Lara and Nora have none. Components with their own `colorScheme` block: Aura 29, Lara 41, Material 29, Nora 31. (`@primeuix/themes-2.0.3:dist/<preset>/index.mjs`)

All four share the same primitive palette and the same default color choices: primary is `emerald`, light surface is `slate`, dark surface is `zinc`. They differ in semantic and component values, for example `semantic.focusRing`: Aura `1px solid {primary.color}` offset `2px`; Nora `2px solid {primary.color}` offset `2px`; Lara and Material `width 0, style none`. (`@primeuix/themes-2.0.3:dist/<preset>/base/index.mjs`)

### Token layers

| Layer                | Location in the preset                 | Content (Aura)                                                                                                                                                                                                                                                           |
| -------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Primitive            | `primitive`                            | `borderRadius` (`none 0`, `xs 2px`, `sm 4px`, `md 6px`, `lg 8px`, `xl 12px`) and 22 color scales, each 50–950: emerald, green, lime, red, orange, amber, yellow, teal, cyan, sky, blue, indigo, violet, purple, fuchsia, pink, rose, slate, gray, zinc, neutral, stone.  |
| Semantic             | `semantic`                             | Scheme-independent: `transitionDuration`, `focusRing`, `disabledOpacity`, `iconSize`, `anchorGutter`, `primary` (palette referencing a primitive scale), `formField` (padding, `sm`/`lg` sizes, radius, focus ring), `list`, `content`, `mask`, `navigation`, `overlay`. |
| Semantic, per scheme | `semantic.colorScheme.light` / `.dark` | `surface`, `primary` (`color`, `contrastColor`, `hoverColor`, `activeColor`), `highlight`, `mask`, `formField`, `text`, `content`, `overlay`, `list`, `navigation`.                                                                                                      |
| Component            | `components.<name>`                    | Per-component sections (e.g. button: `root` with radius, padding, sizes, focus ring, …; `colorScheme.light/dark` with `root`, `outlined`, `text`, `link` variants), optional `css`.                                                                                      |

Values reference other tokens with braces, e.g. button `root.borderRadius: "{form.field.border.radius}"` and Aura light `primary.color: "{primary.500}"`, dark `primary.color: "{primary.400}"` (`@primeuix/themes-2.0.3:dist/aura/button/index.mjs`, `dist/aura/base/index.mjs`).

The `Preset` type is `{ primitive?, semantic?, components?, extend?, css?, [key]: … }`; `extend` adds custom tokens and `css` adds raw CSS (string or `(options: StyleOptions) => string`). `ColorScheme<T>` is `{ light?, dark? }` and `Theme` is `{ preset?: Preset; options?: ThemeOptions }` (`@primeuix/themes-2.0.3:types/index.d.ts`).

### Color schemes and dark mode

Dark mode is a token concern, not a separate theme: every preset carries both `light` and `dark` values in `semantic.colorScheme` and in component `colorScheme` blocks. The engine in `@primeuix/styled` writes light values to `:root,:host` and dark values under `darkModeSelector` (see the options table above), so switching the scheme is a selector change with no new CSS.

## @primeuix/styles 2.0.3

**Purpose.** The structural CSS of each component, independent of any preset. Colors, spacing and radii are not hard-coded; they are `dt('button.primary.color')`-style references that the engine resolves to CSS variables.

**Entry points.** `.` re-exports every module as a namespace named `<Name>Style` (e.g. `ButtonStyle`, `BaseStyle`) (`@primeuix/styles-2.0.3:dist/index.d.mts`); `./*` maps to `dist/<name>/index.mjs`.

**Per-module API.** Each of the 93 modules exports one binding, `style: StyleType` (`@primeuix/styles-2.0.3:dist/types.d.mts`); in 2.0.3 every module's `style` is a plain string (`@primeuix/styles-2.0.3:dist/<name>/index.mjs`).

Modules: the 88 component names that have token objects in `@primeuix/themes`, plus `base` (box-sizing reset and shared keyframes such as `p-animate-collapsible-expand`), `buttongroup`, `checkboxgroup`, `radiobuttongroup`, `scrolltop`, which have styles but no tokens of their own.

### Runtime wiring, in short

Both PrimeNG and PrimeVue hold the active theme in the single `Theme` object from `@primeuix/styled`: their config entry points (PrimeNG's `ThemeProvider`, configured through `providePrimeNG`; the `PrimeVue` plugin in PrimeVue) call `Theme.setTheme(...)`, subscribe to `ThemeService` `theme:change`, load the `common` variables once (guarded by `Theme.isStyleNameLoaded('common')`), and each component's base style calls `Theme.getComponent` / `Theme.transformCSS` for its own variables and its `@primeuix/styles` CSS (`primeng-21.1.9:packages/primeng/src/config/themeprovider.ts`, `primevue-4.5.5:packages/core/src/config/PrimeVue.js`, `primevue-4.5.5:packages/core/src/base/style/BaseStyle.js`).

## Findings worth knowing

- **Version skew in `utils`.** PrimeNG pins `^0.7.2`; PrimeVue pins `^0.6.2`; `@primeuix/styled` 0.7.4 asks for `^0.6.1` and `@primeuix/motion` 0.0.10 for `^0.6.3`. Only PrimeNG's range covers the pinned 0.7.2 archive.
- **PrimeReact 10 is outside the family.** Everything `@primeuix` provides has a separate in-repo implementation in PrimeReact.
- **`@primeng/themes` and `@primevue/themes` add nothing.** Both are re-export shims over `@primeuix/themes` and `@primeuix/styled`.
- **Shared naming.** Server-rendered style tags use `data-primevue-style-id` in every consumer; motion variables use the `--pui-` prefix while theme variables default to `--p-`.
- **Design tokens are not in the framework apidocs.** The token facts for Ultimate live in `@primeuix/themes` (`tokens/` and `types/`), not in `docs/prime-reference/catalog/*.json`.
