# PrimeReact 10.9.9 — notes for component records

Cross-cutting facts that Wave 2 authors need when writing the PrimeReact column of a component record. Back to the [index](index.md).

## Where things live

For a component whose folder is `<folder>` (always lower case, e.g. `dropdown`, `inputswitch`) and whose class is `<Name>` (e.g. `Dropdown`, `InputSwitch`):

| What                                         | Path (relative to `primereact-10.9.9:`)                                  | Notes                                                                                                                                                                                                |
| -------------------------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Import path                                  | `primereact/<folder>`                                                    | From `components/lib/<folder>/package.json`; also re-exported from the all-in-one bundle.                                                                                                            |
| Component source                             | `components/lib/<folder>/<Name>.js`                                      | Plus sub-part files in the same folder (e.g. `DropdownPanel.js`, `CalendarPanel.js`, `UIMessage.js`, DataTable's `BodyCell.js` …).                                                                   |
| Base: default props, classes, structural CSS | `components/lib/<folder>/<Name>Base.js`                                  | `defaultProps` (exact defaults incl. `__TYPE`), `css.classes` (styled-mode class per section), `css.styles` (structural CSS string), `css.inlineStyles`. Exception: InputOtp uses `BaseInputOtp.js`. |
| Types: props, events, methods, pt            | `components/lib/<folder>/<folder>.d.ts`                                  | `<Name>Props`, event interfaces, `<Name>PassThroughOptions`, `<Name>PassThroughMethodOptions`, the class with public methods, `@defaultValue` and `@deprecated` tags.                                |
| Generated API data                           | `components/doc/common/apidoc/index.json`                                | Built from the `.d.ts` files; keyed by folder name (163 entries), each with `components`, `events`, `interfaces`, `types`. The Prime catalog is generated from this file.                            |
| Showcase sections                            | `components/doc/<folder>/*.js`                                           | `importdoc.js`, `basicdoc.js`, one file per feature demo, `accessibilitydoc.js`, `styledoc.js` (style/className usage).                                                                              |
| Pass-through doc                             | `components/doc/<folder>/pt/wireframe.js`                                | Wireframe image of the sections; the page adds a "`<Name>` PT Options" table generated from the `.d.ts`.                                                                                             |
| Theming docs                                 | `components/doc/<folder>/theming/styleddoc.js`, `theming/tailwinddoc.js` | Styled-mode `p-*` class list with the element each targets; the component's section of the Tailwind preset.                                                                                          |
| Page assembly                                | `pages/<folder>/index.js`                                                | Lists `docs`, `ptDocs`, `themingDocs`, `apiDocs` and the page title/description.                                                                                                                     |
| Tailwind preset entry                        | `components/lib/passthrough/tailwind/index.js`                           | Key `<folder>` (flat-case name) in the default export.                                                                                                                                               |
| Global pt type key                           | `components/lib/api/api.d.ts` (`PrimeReactPTOptions`)                    | Missing for some components (see below).                                                                                                                                                             |
| Tests                                        | `components/lib/<folder>/*.spec.js`, `__snapshots__/`                    | Prime's tests are out of scope for the study; mention only if relevant.                                                                                                                              |

## Patterns to describe consistently

1. **Names.** Use the canonical name as the record title and list the PrimeReact name as a legacy alias when it differs: `Dropdown` → Select, `Calendar` → DatePicker, `Sidebar` → Drawer, `OverlayPanel` → Popover, `InputSwitch` → ToggleSwitch, `TabView`/`TabPanel` → Tabs. PrimeReact 10.9.9 has no folder under any of the canonical names, so the PrimeReact column always points at the legacy folder. The page description sometimes acknowledges the new name ("Dropdown also known as Select") (`primereact-10.9.9:pages/dropdown/index.js`). See [index.md](index.md#primereact-only-and-legacy-named-components) for the full list, including PrimeReact-only components (Mention, MultiStateCheckbox, TriStateCheckbox, DataScroller, Messages, InputTextarea, Chips).
2. **Anatomy = pt sections.** The keys of `<Name>PassThroughOptions` are the component's named parts; they match the `cx('<key>')` / `ptm('<key>')` calls in `<Name>.js` and the keys of `css.classes` in `<Name>Base.js`. Each rendered part gets `data-pc-section="<flat key>"`, the root also `data-pc-name`. Nested components appear as their own pt type (e.g. `tooltip?: TooltipPassThroughOptions`), and every pt type allows `hooks?: ComponentHooks` (`primereact-10.9.9:components/lib/inputswitch/inputswitch.d.ts`).
3. **Common props on every styled component**: `pt`, `ptOptions`, `unstyled` (from `ComponentBase.defaultProps`), usually `className`, `style`, `id`, and for form components `invalid`, `disabled`, `tooltip`, `tooltipOptions`, and often `variant: 'outlined' | 'filled'`, which falls back to the context `inputStyle` (`primereact-10.9.9:components/lib/componentbase/ComponentBase.js`, `primereact-10.9.9:components/lib/inputtext/InputTextBase.js`). Any other prop not in `defaultProps` is spread onto the root (or the focusable element) via `getOtherProps`.
4. **Defaults.** Record the default from `<Name>Base.js` `defaultProps` (runtime truth). The `.d.ts` `@defaultValue` tags usually agree but are documentation only; where they disagree, say so.
5. **Styled-mode classes.** `css.classes` in `<Name>Base.js` is the authoritative list of `p-*` classes and the conditions that add them; `theming/styleddoc.js` is the human-readable version. Colours and spacing for those classes come from the theme CSS (`public/themes/<theme>/theme.css`), not from the component.
6. **Theming section of a record** has three PrimeReact facts: the `p-*` classes; the pt section keys; and that there are **no design tokens** — PrimeReact 10 has no `@primeuix` token set, so "design tokens" is `N/A` for the PrimeReact column (see [architecture.md](architecture.md#primeuix-and-design-tokens)).
7. **Icons.** Icon props are typed `IconType<Props>` (string class, element or function receiving `{ iconProps, element, props }`); defaults are SVG components from `primereact/icons/<name>` (see [icons-and-guides.md](icons-and-guides.md#built-in-svg-icon-components-componentslibicons)).
8. **Templates.** Content templates are typed `TemplateType<…>` or `React.ReactNode | ((options) => React.ReactNode)`; React has no slots, so map Vue slots / Angular templates to these props in the framework-differences table (`primereact-10.9.9:components/lib/utils/utils.d.ts`).
9. **Overlays** (Dropdown, Calendar, MultiSelect, OverlayPanel, AutoComplete, CascadeSelect, TreeSelect, Password, …) share: `appendTo` prop (`'self'`, element, function; falls back to context then `document.body`) rendered through `Portal`; `CSSTransition` with `transitionOptions`; `ZIndexUtils` with the context `zIndex` group (`overlay`, `modal`, `menu`, `tooltip`, `toast`); `useOverlayListener` for outside click / resize / scroll; `OverlayService` `overlay-click` (Dropdown, TreeSelect). Escape handling is not uniform: Calendar, CascadeSelect, ColorPicker, ConfirmPopup, Dialog, Galleria, Image, Menu, OverlayPanel, Password, Sidebar, SlideMenu, SpeedDial, SplitButton and Tooltip register through `useGlobalOnEscapeKey` with an `ESC_KEY_HANDLING_PRIORITIES` value plus `useDisplayOrder`; others (e.g. Dropdown) handle Escape in their own key handlers (`primereact-10.9.9:components/lib/portal/Portal.js`, `primereact-10.9.9:components/lib/hooks/useGlobalOnEscapeKey.js`, `primereact-10.9.9:components/lib/dropdown/Dropdown.js`).
10. **Locale-dependent text** (empty messages, aria labels, calendar names) comes from `localeOption` / `ariaLabel` in `primereact/api`; list the keys a component reads, from `Locale.js` (`primereact-10.9.9:components/lib/api/Locale.js`).
11. **Accessibility** facts: take roles/ARIA from the JSX in `<Name>.js` and the keyboard table from `components/doc/<folder>/accessibilitydoc.js`. The general guide noted that the accessibility review was still being ported to PrimeReact, so per-component sections can be thinner than PrimeVue's; record differences rather than assume parity (`primereact-10.9.9:components/doc/accessibility/introductiondoc.js`).
12. **Dependencies section.** Internal: the relative imports at the top of `<Name>.js` (e.g. `../api/Api`, `../componentbase/ComponentBase`, `../hooks/Hooks`, `../utils/Utils`, `../csstransition/CSSTransition`, `../portal/Portal`, `../tooltip/Tooltip`, `../virtualscroller/VirtualScroller`, icon folders). External: only `react`, `react-dom`, `react-transition-group` for almost everything; Chart needs `chart.js` and Editor needs `quill`, both loaded with dynamic `import()` and not declared as dependencies (`primereact-10.9.9:components/lib/chart/Chart.js`, `primereact-10.9.9:components/lib/editor/Editor.js`).
13. **Deprecations.** PrimeReact marks deprecations only in `.d.ts` comments; none of the legacy-named components is itself deprecated. Deprecated members found in the archive: `DropdownFilterOptions` and Dropdown `filterTemplate` (`@deprecated Since v9.3.0`), Toolbar `left` / `right` (`use start` / `use end instead`), SelectButton `unselectable` (`Use 'allowEmpty' property instead.`), Image `template` (`Since v9, use indicatorIcon instead`), VirtualScroller `loaderIconTemplate` (`Since v9.2.3, use loadingIcon instead`), DataTable `responsiveLayout` (`since version 9.2.0`), StyleClass `enterClassName` / `leaveClassName` (`since 10.5.2`), and the static `PrimeReact` config (`since version 9.6.0`) (`primereact-10.9.9:components/lib/dropdown/dropdown.d.ts`, `primereact-10.9.9:components/lib/toolbar/toolbar.d.ts`, `primereact-10.9.9:components/lib/selectbutton/selectbutton.d.ts`, `primereact-10.9.9:components/lib/image/image.d.ts`, `primereact-10.9.9:components/lib/virtualscroller/virtualscroller.d.ts`, `primereact-10.9.9:components/lib/datatable/datatable.d.ts`, `primereact-10.9.9:components/lib/styleclass/styleclass.d.ts`, `primereact-10.9.9:components/lib/api/api.d.ts`).

## Known type/runtime gaps

Worth a line in the affected record when relevant:

- Global pt keys missing from `PrimeReactPTOptions` although the component calls `ptm`: `buttongroup`, `datascroller`, `iconfield`, `inputicon`, `metergroup`, `stepper`, `tristatecheckbox`; and `inputmask` is typed with `InputTextPassThroughOptions` (`primereact-10.9.9:components/lib/api/api.d.ts`).
- `useMove`, `useStyle`, `useClickOutside` declarations differ from their implementations ([hooks.md](hooks.md)).
- `utils.d.ts` and the runtime classes differ in a few members ([api-and-utils.md](api-and-utils.md#primereactutils)).
- The context setters `setPtOptions` and `setUnstyled` exist at runtime but are undeclared ([index.md](index.md#configuration-options-apioptions)).
